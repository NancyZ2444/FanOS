## 1. 产品目标与本版决策

用户只记得小卡的服装、动作、背景或大致画面时，可以输入自然语言，从平台已发布图鉴中找到可能对应的小卡，再进入原详情确认。

示例：“找某艺人黑发、白色上衣、蓝背景、在脸旁比耶的那张。”

本版确定以下规则：

1. 新卡发布后自动建立图片语义索引，无需运营先填写或确认视觉标记。
2. 图片索引与文字描述直接匹配，图片上的可读标签不是检索前置条件。
3. 原艺人、组合、来源、年份等正式资料用于精确筛选；服装、发色、动作等视觉描述用于相似度排序。
4. 视觉描述属于偏好，首期不提供“视觉特征必须完全满足”的筛选开关。
5. 必要时由视觉模型核对少量候选，提高排序质量；不在每次查询时重新识别整个图鉴。
6. App 展示真实图片与正式图鉴信息，默认不展示模型编写的逐字段匹配理由。
7. 后台以自动索引、失败重试、质量抽检和问题纠正为主，取消图片标记逐卡审批。
8. 图鉴录入、正式审核、用户贡献、已拥有、心愿和数字相册关系继续沿用原规则。

### 1.1 与 V1.0 的关键变化

| 项目 | 本版规则 |
| --- | --- |
| 图片是否必须有文字标记 | 不需要；语义索引就绪即可参加描述检索 |
| AI 标记是否需要人工逐条确认 | 不需要；可选增强字段通过自动校验后用于辅助排序，不确定就留空 |
| 默认后台工作量 | 查看异常、抽检和处理有效问题，不产生全量待审核任务 |
| 视觉严格筛选 | 首期移除，避免将不完整识别当成确定判断 |
| 标记纠错审批 | 获得相应权限的运营可直接保存生效，保留版本和撤销记录 |
| 正式图鉴审核 | 保留；AI 搜索处理不替代原审核 |

### 1.2 目标与业务指标

关注找到目标的效果及每次找卡成本：固定评测集 Top 5 / Top 20 命中率、用户明确确认找到的比例、平均有效轮数、真实零结果率、索引覆盖率、响应时间、会话费用和人工处理时长。

用户未点击“就是这张”不能直接认定找卡失败；结果点击、明确确认和退出需要分别统计。机器生成标签数量与回答字数不作为成功指标。

## 2. 当前系统基础与新增能力

以下“当前”依据本工作区已有实现，未连接生产环境核验。

| 能力 | 当前基础 | 本次新增 / 调整 |
| --- | --- | --- |
| App 图鉴搜索 | 名称、编号、来源、版本、标签等文字检索；支持多类对象 | 新增只找小卡的描述入口与独立页面 |
| 小卡图库 | 组合、艺人、来源、年份、正式标签等筛选及详情跳转 | 复用正式对象、卡片资料与详情，增加语义排序 |
| 图片扫描 | 核心匹配使用局部图像特征与几何核验，查找对应卡图 | 保留原用途；新增适配文字找图的图文语义索引 |
| 小卡管理 | 录入、关系校验、送审、发布、下架、图片版本 | 在正式发布后增加异步索引任务 |

| 图片事件与任务 | 已有 Outbox；当前扫描任务主要消费正面图片更新 | 补齐发布、背面、换图、主资料、下架、合并、删除等检索同步 |
| 用户反馈 | 缺卡收录、资料纠错、提交者关联及进度 | 搜索质量单独统计；正式资料问题继续复用原纠错 |

现有扫描索引不能直接当作文字语义索引使用。可复用图片存储、Card ID、事件基础和任务管理思路，检索模型与索引内容需新增。

## 3. 范围、对象与权限

### 3.1 本期范围

纳入：文字描述、正式对象范围、正背面检索、连续补充、真实结果、历史记录、额度、自动建库、索引管理、按需候选核对、质量反馈、抽检和图鉴生命周期同步。

可选增强：自动视觉标记、图片中可见文字 OCR、简短图片描述。独立配置开关，关闭后核心找卡流程必须可用；首发默认关闭这些额外建库调用，试点评估有明确收益后再启用。

不在本期：素材生成、动态小卡 / Live 图、语音输入、上传照片与文字混合查询、全网搜卡、自动新建图鉴、自动训练用户专属模型。用户有照片时继续使用原 AI 扫描入口。

### 3.2 数据范围

- 仅检索当前已发布、在公开范围内且用户有权访问的小卡；存在图片索引不代表有公开资格。
- 正背面分别处理，返回时按真实 Card ID 合并；不同 Card ID 的近似版本不能擅自合并。
- 小卡身份、来源、版本和贡献信息读取正式数据库，模型不得根据外貌推断后覆盖。
- 私人备注、拥有与心愿关系仅在本人权限范围应用，不成为全局图鉴别名或共享索引内容。
- 扫描历史或已拥有页允许查看的下架卡，不因此重新进入描述搜索结果。

### 3.3 角色与权限

| 角色 | 能力 |
| --- | --- |
| 游客 | 查看介绍与示例；点击找卡后登录并恢复输入 |
| 登录用户 | 发起查询、补充描述、管理本人历史、查看结果和反馈质量 |
| 内容运营 | 查看索引与异常、有限范围重试、处理质量问题；获“检索纠错”权限后可直接修正搜索附属信息 |
| 管理员 | 配置模型、预算、范围、批量重建、停用与回滚；授予检索纠错权限 |
| 其他角色 | 沿用现有权限范围，不自动获得图鉴和 AI 管理权限 |

“检索纠错”是新增权限，不等于现有图鉴发布、删除、合并或正式资料编辑权限。检索纠错直接生效，不再增加管理员二次确认；所有修改仍需记录原因、操作者、时间、前后值及版本。

## 4. 工作原理与处理流程

### 4.1 小卡发布后的自动处理

小卡审核发布 → 事务事件 → 获取当前正背面图片 → 图片质量 / 版本检查 → 生成图片向量 → 写入检索索引 → 该图片可参与找卡。

图片向量是机器比较画面含义的一组数字，不是必须由人填写的标签清单。新增图片通常只需计算并保存其特征，不需要重新训练模型。图像与文字编码必须来自兼容的语义空间；图文特征比较可参考 [CLIP 官方库文档](https://huggingface.co/docs/transformers/model_doc/clip)。本文不指定最终供应商或模型。

原发布成功和索引就绪分别记录。识别失败、排队或检索服务故障不回滚原卡发布。

### 4.2 用户查询流程

1. 理解用户描述，分离正式范围与视觉偏好；正式对象存在歧义时先确认。
2. 对当前已发布且满足正式条件的全体数据进行检索，包括“只看已拥有”等本人关系限制。
3. 将视觉描述转换为与图片兼容的查询特征，同时可召回正式名称、编号、来源和既有标签的关键词结果。
4. 合并图片语义与关键词候选，按真实 Card ID 去重，保留匹配面与版本。
5. 触发条件满足且预算允许时，对少量候选做视觉核对并调整排序。
6. 再次检查当前可见性、正式条件、图片版本和会话排除项，读取正式图鉴数据展示。
7. 需要缩小范围时给出一个可跳过的追问，用户确认后再执行下一轮。

单纯向量相似分数不是正确率。模型提供的 Card ID 必须来自服务端候选集合，不能生成新的图鉴记录。

### 4.3 正式条件与视觉偏好

| 类别 | 示例 | 处理 |
| --- | --- | --- |
| 正式精确条件 | 某艺人、某组合、指定来源、年份、正式标签 | 对应明确的正式对象 / 值后精确筛选，不能静默放宽 |
| 关系与图片条件 | 只看已拥有、正面 / 背面 | 由业务关系与实际图片面过滤 |
| 视觉偏好 | 黑发、白衣、蓝背景、比耶、自拍构图 | 调整召回与排序，不声称每张卡全部满足 |
| 不确定描述 | 好像红发、可能拿花 | 保留不确定性，降低约束强度 |
| 视觉否定 | 不戴帽子、不要红背景 | 作为“尽量排除”的偏好；未知不等于确认不存在 |

用户明确要求“必须白衣”“绝对不要帽子”时，执行前提示：“当前按画面相近推荐，无法保证所有视觉条件都符合。”提供“按偏好查找 / 修改描述”，选择后显示“偏好：白衣 / 尽量排除帽子”。不把严格要求无提示地改成偏好；确认本身不单独计费。

同一画面描述的特征按同一图片面理解；同一人的动作、服装等按同一主体理解。仅用户明确“正面 X、背面 Y”时才按两面分别检索与合并。不能把正面黑发与背面蓝背景解释成同一画面“黑发蓝背景”，也不能跨人物编造符合关系。

### 4.4 按需候选核对

| 项目 | 规则 |
| --- | --- |
| 触发 | 候选高度相近且难区分、多人物 / 多条件组合、用户补充了关键画面细节；由经评测的策略判断 |
| 规模 | 建议每有效轮最多核对 10 张图片；是图片数，正背面分别占用，配置调整需验证时延与成本 |
| 输入 | 当前描述、允许的正式条件、少量当前有效候选图片及受控 ID |
| 输出 | 候选间的相对相关性、无法判断的项及内部核对依据；只用于本轮排序 |
| 权限 | 不修改正式资料，不生成新候选卡，不将“这次不相关”改成全局禁用 |
| 失败 | 已有有效语义结果时，返回初排候选；不把核对失败显示成找不到卡 |
| 时间与次数 | 纳入本轮总时限和用户分析额度；不另扣一次，不在翻页时自动重复调用 |

核对是可关闭的增强步骤，关闭不影响核心向量检索。结果正式呈现后不因迟到核对自动跳动排序；如核对超时，冻结初排结果，后到结果只用于诊断。App 不展示“人工已确认”或“100% 匹配”。

## 5. App 入口与页面结构

沿用首页、图鉴、扫描、收藏、我的底部导航，不增加一级 Tab。

| 页面编号 | 页面 / 入口 | 布局重点 |
| --- | --- | --- |
| FC-A01 | 图鉴入口 | 搜索框旁或下方“找卡 AI”，说明“描述画面找小卡” |
| FC-A02 | 初始页 | 输入、范围、示例、额度、找卡记录 |
| FC-A03 | 结果页 | 条件摘要、双列网格、追问、继续描述 |
| FC-A04 | 条件面板 | 正式筛选与视觉偏好分区 |
| FC-A05 | 确认面板 | 同名对象、范围冲突、不支持的严格视觉要求 |
| FC-A06 | 找卡记录 | 本人会话、描述轮次、结果与删除 |
| FC-A07 | 质量反馈 | 不符合描述、理解有误、结果不准确等 |
| 复用 | 原小卡详情、AI 扫描、图鉴纠错 | 延续既有操作和状态 |

### 5.1 入口带入

| 入口 | 默认行为 |
| --- | --- |
| 图鉴首页 | 全部图鉴，输入为空 |
| 普通搜索的小卡区域 / 无结果页 | 带入已有文字，用户点击开始后才调用 AI |
| 扫描页“没有图片？描述找卡” | 进入文字页，不自动提交扫描照片或缺卡反馈 |
| 艺人 / 组合详情的小卡列表 | 带入正式对象 ID，显示可移除的范围条件 |
| 已拥有列表 | 首期不增加专属入口，结果页提供本人拥有筛选 |

从带入某艺人的页面输入另一艺人时，提示替换范围或修改描述，不能默默选一个。返回原页面保留原浏览位置。

### 6.1 页面布局

```text

┌───────────────────────────────────────┐

│ 手在脸旁比耶的那张……                   │

                                             0/500

[蓝背景、戴帽子的自拍卡]
```

### 6.2 交互规则

- 输入 1～500 个用户可见字符；去掉首尾空白后不能为空。未要求必须填写某一个特征。
- 点击示例只填入文本，可编辑，不自动调用、不消耗次数。
- 范围选择支持组合 / 艺人；默认全部，不要求先知道来源或版本。
- 点击开始前校验登录、功能可用性、输入与额度，服务端重复校验。
- 登录中断、网络失败和返回页面保留草稿；账号切换清理原账号草稿。
- 提交中禁用重复点击，显示“正在找卡”；允许离开，稍后从记录恢复请求。
- 不随输入实时调用模型；提交动作才触发查询。
- 键盘弹起时输入和提交可操作，适配安全区域、大字体和读屏；条件类型不只用颜色区别。

默认每页 20 张，本轮最多提供 100 张推荐候选。它是推荐上限，不等于图鉴内实际只有这些卡；分页沿用该轮稳定顺序，不再次分析。

### 7.2 卡片与操作

| 元素 / 操作 | 要求 |
| --- | --- |
| 卡面 | 保留边框和文字，不为填满网格裁掉关键信息；无可用图用占位，不生图补齐 |
| 正背面 | 按命中面展示并标识，可查看另一面；同一卡合并为一个结果 |
| 正式资料 | 艺人 / 组合、来源、版本从图鉴读取；沿用个人显示名偏好，不改实际对象 ID |
| 匹配说明 | 首期使用“画面相近，建议核对”；不逐条宣称“已识别白衣 / 已确认比耶” |
| 拥有 / 心愿 | 读取本人关系，只读标识 |
| 点击卡片 | 跳转原小卡详情，返回保留条件、排序与滚动位置 |
| 更多 → 就是这张 | 记录本轮找到目标并进入详情；不自动设置已拥有或心愿 |
| 更多 → 不是这张 | 在当前会话排除，有撤销入口，不全局降权或下架该卡 |
| 更多 → 图鉴信息有误 | 打开原纠错页面，自动带入对应小卡 |
| 结果页 → 反馈找卡问题 | 打开质量反馈，不与正式资料修改混为一项 |

不显示未经校准的“正确率 98%”。同画面但来源不同的真实小卡继续分别展示，用来源 / 版本帮助辨认。

### 7.3 条件编辑面板

| 区域 | 可调整内容 | 提交与次数 |
| --- | --- | --- |
| 正式范围 | 组合、艺人、来源、年份、正式标签 | 已解析对象通过选择器修改，点击“应用筛选”，不消耗 AI 分析轮 |
| 本人关系 | 只看已拥有 | 点击应用后从完整符合范围的集合重查，不只过滤当前页 |
| 图片面 | 不限 / 正面 / 背面 | 仅改变检索面且不改视觉语义时，按结构化筛选处理 |
| 画面偏好 | 已解析特征、记忆不确定、尽量排除 | 删除、增加或纠正会改变描述，点击“重新分析 · 使用 1 轮” |

面板分别显示已应用与待提交内容。放弃编辑恢复原条件，旧结果不能提前显示为符合新条件。混合修改正式范围和视觉偏好时，一次提交完成并只计一轮。

若原描述明确分配了两面特征，切成单面导致语义冲突，提示保留双面或编辑描述；不能免费切面时偷偷重写用户描述。

正式范围不存在或无卡时明确提示，不能擅自移除艺人 / 来源来凑结果。视觉偏好不提供“必须符合”按钮。

## 8. 多轮、反馈、历史与异常

### 8.1 多轮处理

| 输入 / 动作 | 行为 |
| --- | --- |
| “不是白色，是黑色衣服” | 替换服装偏好，保留其他兼容条件 |
| “好像拿着花” | 增加不确定偏好 |
| “是某艺人的” | 确认正式对象后调整范围；自由文字需理解时计本轮 |
| “不是这个组合” | 要求确认要移除 / 替换的正式对象，避免误解指代 |
| “不要帽子” | 显示“尽量排除帽子”，涉及明确严格要求时先按第 4.3 节确认 |
| “重新找” | 提供修改本轮或清空新建，不暗自丢弃条件 |
| 追问“不确定 / 跳过” | 保留当前结果与条件，不计新轮，不重复追问同一问题 |
| 回到历史轮继续 | 明确以选中轮为基准创建后续轮，原记录不被覆盖 |

一次最多一个追问，提供 2～4 个选项及“不确定”。正式主体歧义必须确认；视觉追问可跳过。追问仅在有助于区分候选时出现，不能为了增加轮数重复提问。

首轮消歧或严格视觉能力确认时，原请求进入“等待用户确认”，可尚无有效轮次。使用原请求 ID 与选择恢复，不新建会话、不重复预占。默认等待 10 分钟；取消 / 到期释放预占，保留输入。等待阶段不占模型并发。

### 8.2 找卡质量反馈

类型建议：理解错了描述、结果普遍不相关、目标已在图鉴但没找到、其他。用户可补充最多 500 个用户可见字符；知道目标时可选择已有 Card ID，不要求必须找到目标才能反馈。

提交只生成质量记录，不自动修改标签、卡片或全局排名。后台可合并同一问题的重复反馈并保存关联。单次“不是这张”作为普通行为统计，不逐条派人工任务。

正式资料错误继续走原图鉴纠错，其进度仍在既有扫描反馈中心查看；本功能质量反馈只提示“已收到”，本期不新增一个面向用户的工单进度中心。缺卡反馈仍由 AI 扫描缺失场景发起，文字搜不到不能直接新建卡。

### 8.3 历史和返回

- 找卡记录按最近使用时间排列，展示描述摘要、时间、结果缩略图、轮数和是否可继续；支持单条删除与清空。
- 详情记录展示每轮已应用条件、结果及状态，返回时恢复滚动位置和会话排除项。
- 默认会话 24 小时内可继续，共最多 5 个有效分析轮；可读历史保留最近 30 天。
- 已过期会话可查看并按原解析条件刷新当前可见结果；新描述或修改视觉偏好需确认新会话。
- 历史结果每次展示前检查当前公开状态、正式筛选和图片版本；换图后的旧排序不得伪装成新图匹配，提示刷新。
- 删除历史不返还正常使用的额度。原文与可读历史按删除策略清理，最小化的费用审计独立留存。
- 历史只属于本人，切换账号清理页面缓存与待提交内容。

### 8.4 查询状态与异常

| 状态 | App 行为 | 用户额度 |
| --- | --- | --- |
| 正常候选 / 较弱相近结果 | 展示真实候选与相近推荐提示 | 计有效轮 |
| 正常零结果 | “暂未找到”，提供调整描述 / 范围及扫描入口 | 计有效轮 |
| 精确范围或已拥有筛选为空 | 提示范围内暂无结果，支持主动移除筛选 | 纯筛选不计轮 |
| 候选核对不可用，但语义检索成功 | 返回初排结果，不中断 | 计有效轮，无额外次数 |
| 核心语义检索失败，仅能普通搜索 | 明示“AI 找卡暂不可用，以下为普通搜索结果” | 不计失败轮，首轮不结算 |
| 系统故障 | 保留草稿及上一轮结果，标明本轮未更新 | 不扣失败轮 |
| 客户端超时、服务端状态未知 | 查询原请求，不创建新付费请求 | 等最终状态 |
| 次数 / 轮数不足 | 可查看结果，新分析前明确新会话或额度说明 | 不静默扣次 |
| 卡片下架、删除或权限变化 | 移除结果或显示不可访问 | 不补扣 |

同会话任一时刻只执行一个结果更新请求，包括分析、结构化重查和刷新。处理中可编辑下一轮草稿，提交操作等待完成；请求 ID 与查询版本防止重复结算和迟到响应覆盖。

单次执行默认总时限 60 秒，服务端在截止点原子确定成功或失败；等待用户确认独立按 10 分钟计时。截止前成功的请求可以恢复；截止后仍未提交有效结果则失败、释放预占并解除占用。迟到模型输出只记实际费用，不重新扣用户次数、不写回已结束轮次。

## 9. 原小卡新增与收录流程

### 9.1 后台手工新增

1. 按原表单填写组合 / 艺人、来源、版本及图片，原关系与必填校验继续生效。
2. 保存草稿，按原流程提交图鉴审核。默认不对每次保存草稿自动发起付费识别。
3. 审核发布事务成功，投递对应 Card ID 与修订版本的索引事件。
4. 后台独立处理正背面图片，完成后自动可检索；原卡不需要再次审核。
5. 索引失败显示原因并重试，原卡仍保持发布成功。

新增 / 详情页增加折叠区“找卡 AI 检索”，无需输入：

```text
找卡 AI 检索
正式图鉴：已发布
正面：已就绪        背面：处理中 / 无背面
最近更新：...
[查看任务] [重试失败项]
提示：发布后自动处理图片，不需要填写检索标签。
```

草稿页显示“发布后自动建立索引”；首期不在录入步骤安排视觉标记表单或人工确认按钮。后台管理员的测试工具可预处理草稿，但必须独立授权、计费并隔离公开结果，不作为日常新增路径。

### 9.2 缺卡转图鉴与贡献

扫描缺卡反馈 → 后台一键转原小卡草稿 → 确认正式资料 → 原审核发布 → 原收录状态与用户贡献生效 → 自动加入找卡索引。

用户提交图片的来源类型、来源链接豁免、提交者与图片版本关联保留。AI 索引不会把用户图片来源改成平台原创，也不产生新的贡献人。索引失败不撤销“已收录”，不影响我的贡献仅展示已收录小卡的既有规则。

### 9.3 批量新增和正式资料修改

批量导入 / 生成沿用先草稿、后审核发布。发布后拆分异步任务，显示成功、待处理、失败及逐项原因，不在原发布请求内同步计算图片。

当前主卡保存逻辑拒绝直接编辑已发布卡；正式资料仍按原下架、编辑、送审、发布执行。仅修正检索附属信息采用独立接口，不调用主卡保存，不要求下架。

## 10. 小卡生命周期与检索同步

| 事件 | 必须处理 | 是否重做图片计算 |
| --- | --- | --- |
| 新增 / 导入草稿 | 不进入公开检索 | 默认不计算 |
| 首次正式发布 | 同步主资料，按当前正背面建索引 | 缺少有效索引的图片计算 |
| 同图重新发布 | 恢复公开资格，校验当前版本 | 可复用兼容的有效结果 |
| 正式艺人 / 组合 / 来源 / 年份 / 标签改变 | 更新正式筛选与关键词资料 | 图片未变则不重算 |
| 更换正面 | 立即禁用旧正面索引与核对缓存，重建正面 | 仅正面 |
| 更换背面 | 独立触发，禁用旧背面并重建 | 仅背面 |
| 删除背面 | 移除背面检索项与缓存 | 不需要 |
| 同 URL 替换内容、裁切成新图 | 按内容指纹识别变化，旧结果失效 | 对变化图片重算 |
| 图片转存或仅来源说明变化 | 核实实际内容一致后更新关联 | 相同内容可复用 |
| 正式资料纠错采用并重发 | 依据最终提交字段、最终发布版本更新 | 仅改图时需要 |
| 下架 / 归档 | 查询返回层立即排除，索引异步停用 | 不需要 |
| 恢复归档为草稿 | 仍不公开，等待重新发布 | 发布时检查 |
| 删除 | 清理检索关联，阻止迟到任务复活 | 不需要 |
| 合并 A 到 B | 停用 A，更新 B 的最终资料和图片；按主卡去重 | 只处理 B 当前图片，不盲目复制 A 特征 |
| 关联艺人 / 组合 / 来源改名或别名更新 | 按依赖刷新受影响卡的正式检索信息 | 不需要 |
| 关联对象隐藏 / 权限变化 | 按最新规则过滤，不泄漏隐藏信息 | 不需要 |
| 可选搜索附属信息纠错 | 更新辅助排序数据，失效相关查询缓存 | 不重算图片向量 |
| 向量模型 / 预处理版本升级 | 建新版本并评测、灰度切换 | 按版本需要重建 |

### 10.1 当前需要补齐的事件

已有扫描 worker 主要处理正面更新，描述检索必须补齐发布、背面更新、主资料、合并、删除及关联对象变化。不能仅接入已有扫描事件就认为同步完整。

当前 Outbox 使用单个消费完成标记。新增描述检索不能与扫描 worker 竞争同一事件后相互漏消费；须采用独立描述事件，或按消费者分别记录投递 / 完成状态。两类任务失败、重试与完成独立，不因一个功能处理成功而跳过另一个。

纠错流程可能在同一事务里先下架、保存、送审再发布。事件消费者以最终提交状态和单调修订号为准，迟到的旧下架事件不能删除新发布结果。数据库事务失败不得产生可公开检索的新版本。

### 10.2 版本、缓存和幂等

索引处理身份至少包括 Card ID、图片面、内容指纹、目标修订、向量模型及预处理版本。写回前检查当前源数据，过期任务只记“已过期”。相同内容可缓存复用计算结果，但不同卡的身份、权限、来源及关系分别保存，不因同图自动合并卡。

换图、下架、合并、正式范围变化均使相关结果 / 核对缓存失效。全局缓存不得含本人拥有、私人备注和查询原文；服务端每次返回前再次应用最新正式范围与用户权限。模型空间不兼容时禁止混查旧向量。

## 11. 后台：检索资料与索引

### 11.1 菜单与页面

图鉴内容管理下新增“找卡 AI”，首期包含三个页面：

1. 检索资料与索引：看覆盖、状态、错误和任务。
2. 搜索质量：看查询效果、反馈、抽检和纠正。
3. AI 配置与任务：场景开关、模型、额度、预算和批量处理。

已有“AI Scan 索引”保留。找卡 AI 不新增“每张卡等待标记审批”的必经工作台。

```text
小卡        原卡状态    正面索引    背面索引    最近处理    操作
```

### 11.3 单卡检索详情

| 区域 | 内容 |
| --- | --- |
| 原卡信息 | 当前正背面、正式身份 / 来源、发布状态、原图鉴详情入口 |
| 检索范围 | 主资料可检索性、语义检索启用情况、本功能排除状态及原因 |
| 正背面索引 | 当前图片版本 / 指纹、当前有效索引、目标索引、处理阶段与更新时间 |
| 任务记录 | 图片读取、向量生成、索引写入，各阶段状态、实际尝试、费用、错误 |
| 可选增强 | 未启用 / 自动生成 / 人工修正 / 停用；未启用不显示待办 |
| 操作记录 | 操作人 / 系统、时间、原因、前后值及关联任务 |

不要求运营查看或编辑数字向量。界面应回答“为什么这张卡还搜不到”“哪一面出了问题”“是否需要重试”。

### 11.4 索引与任务状态

| 图片索引状态 | 检索行为 |
| --- | --- |
| 未建立 / 已排队 / 处理中 | 当前面暂不提供视觉召回；正式关键词可按公开规则参与 |
| 已就绪 | 当前图片、模型与空间有效，自动参加检索 |
| 更新中 | 同图且当前查询空间兼容的旧索引可继续用；换图旧索引立即禁用 |
| 失败 | 展示阶段、原因与重试，原卡不受影响 |
| 已过期 | 图片、修订或模型不符，不允许当当前索引使用 |
| 已暂停 | 停止该面语义检索，保留审计；恢复前重新校验 |
| 无对应图片 | 不建索引、不算失败 |

任务状态另记：待执行、执行中、成功、失败、已过期、取消。索引就绪不代表可选标记或 OCR 已完成；在线候选核对也不改变索引状态。

### 11.5 操作规则

- 单项 / 批量重试只处理失败或缺失的必要阶段；索引写入失败但向量已成功时，复用计算结果。
- 批量处理须明确选择范围，预览卡数、图片数、模型版本、费用估算与预算上限。
- 暂停批次停止新任务派发；已被供应商接受的调用仍可能产生成本，后台展示实际状态。
- 取消批次不删除已有有效索引；重建索引不删除人工修正记录。
- 暂停语义检索不影响普通关键词能力；若需从找卡 AI 整体排除，管理员另设开关和原因。二者均不改变图鉴发布状态。
- 恢复任务或检索前核验当前版本和发布状态，不能将旧图或已删除卡恢复到结果中。

### 12.2 问题处理

| 问题 | 处理动作 |
| --- | --- |
| 目标卡没有有效索引 | 跳转任务，重试或处理图片读取问题 |
| 已有索引但漏召回 / 排序靠后 | 加入困难样本，检查查询理解、模型或排序策略 |
| 模型把白衣理解为白背景 | 记录查询理解错误，更新模板 / 评测；不直接改原卡 |
| 正式艺人、来源、图片错误 | 进入原图鉴编辑 / 纠错流程 |
| 可选机器标记错误 | 授权运营直接修改 / 停用，保留审计，无需二审 |
| 用户仅表示“不是这张” | 作为会话反馈统计，不自动创建人工待办 |
| 图鉴尚未收录 | 记录检索覆盖问题；需要照片时引导原扫描反馈路径 |

质量问题状态：待处理 → 处理中 → 已处理；重复或无需处理可以关闭并填写说明。这里是后台问题状态，不改变小卡的“已收录”等用户反馈状态。

关闭问题应记录结论和关联动作；有标准目标的样本需要重放验证。运营不能通过把目标卡固定置顶或写死某个用户的查询，替代整体检索质量修正。

### 12.3 抽检与人工预算

首次上线前建立代表性评测集，覆盖不同组合 / 艺人、正背面、近似版本、多人、模糊描述、否定与无目标场景。人工确定目标卡及可接受候选，不用模型自评作为真值。

日常按字段 / 描述类型、模型版本、图片类型、查询热度分层抽检，配置抽检数量、比例及人工处理上限。优先明确反馈错误、重复出现的问题和高频查询；保留一定随机样本，避免只看到高频成功案例。

不确定特征可以留空、可选增强可停用，不把所有低分结果转成人工任务。向量分数及模型自报置信度不得直接当作准确率或统一放行线；阈值和触发策略用真实小卡样本评测确定。

同类问题可聚合处理；一次修正记录影响范围并重新评测。新模型或新图片类型上线时增加抽检，稳定后按实际错误率调整。人工处理量是运营预算，不是每张卡必须完成的步骤。

### 12.4 轻量纠错与版本保护

具备“检索纠错”权限的运营，对可选附属信息可直接修改、停用、恢复或撤销；提交时校验图片与字段版本，冲突时要求核对差异。人工修正优先，当前图片未变时自动重跑不能覆盖。

纠错只涉及搜索附属资料，不接受 Card.status、艺人、来源、图片贡献者等主数据字段。停用错误内容立即从辅助排序中排除；异步更新期间显示“修正已保存，检索资料更新中”。

如果首发没有启用可选标记，不要求人工补建标记来结案，可直接处理索引、查询理解或模型问题。

## 13. 可选增强：自动标记、OCR 与图片描述

本章为独立可选能力，默认关闭额外生成调用。研发和验收不得把这些字段非空当作图片索引就绪条件。

| 内容 | 可选字段 | 使用范围 |
| --- | --- | --- |
| 可见特征 | 发色、服装 / 颜色、手势、配饰、手持物、背景、构图、人物数量 | 辅助召回 / 排序，不做严格视觉排除 |
| 图片文字 | visible_text | 文字线索召回，不作为官方卡名、艺人、来源的认定依据 |
| 简短描述 | visual_summary，最多 500 个用户可见字符 | 补充语义文字，不编造发行事实 |
| 上下文 | Card ID、图片面 / 版本 / 指纹、主体范围 | 防止跨图、跨面、跨人物拼接 |
| 追溯 | 来源、模型 / 模板版本、规则版本、时间、修改人与理由 | 追踪自动生成与人工修正 |

启用后，格式、受控词汇、图片版本与经评测的字段规则校验通过即可用于辅助排序；不确定就留空，矛盾项停用，不进入全量待审核队列。未识别到“帽子”不代表确认没有帽子。

字段状态为未启用、自动可用、已人工修正、已停用、已失效；生成失败另记任务错误，不阻塞图片向量。管理员可按字段 / 模型版本整体停用，快速消除一类错误的影响。

正式标签与可选视觉字段隔离，不自动追加到 Card.tags。不同维度的“蓝色”分别管理；正式身份仍使用主数据。词典采用平台预设和版本管理，不在首发新增复杂词条审批流程。

首期 App 不展示这些字段为已确认事实。后续若要增加具体匹配说明或严格视觉筛选，需单独评测并更新产品规则，不能仅因字段存在便开放。

输入文本、OCR 与图片内容均按数据处理，不能变成修改系统配置或图鉴的指令。模型没有主数据写权限。供应商故障切换只限已验证的兼容能力；没有兼容向量服务时按降级规则处理，不混用旧索引。

## 15. 额度、收费与成本规则

### 15.1 用户计次

建议按“会话”扣找卡次数：1 次会话包含最多 5 个有效分析轮，24 小时内继续。免费 / 会员月额度与售价另行确定。

| 动作 | 会话次数 | 分析轮数 |
| --- | --- | --- |
| 看入口、填示例、改草稿 | 不扣 | 不扣 |
| 首次有效分析，含正常零结果 | 扣 1 次 | 使用第 1 轮 |
| 同会话补充文字、改视觉偏好 | 不再扣会话 | 成功后使用 1 轮 |
| 点击自拍 / 舞台等视觉追问选项并确认更新 | 不再扣会话 | 使用 1 轮；按钮形式不改变计次规则 |
| 原请求消歧、确认按偏好查找、跳过追问 | 不重复扣 | 不单独计轮；原请求真正执行后按本轮结算 |
| 选择已知正式对象、来源、年份、标签、拥有或图片面 | 不扣 | 纯结构化重查不扣 |
| 分页、详情、确定卡 ID 的排除 / 撤销 | 不扣 | 不扣 |
| 系统数据变化后的原条件刷新 | 不扣 | 不扣，不携带新视觉描述 |
| 系统自动进行候选核对 | 包含在本轮 | 不额外计轮 |
| 核心语义服务失败、仅返回普通搜索 | 不结算首轮 | 不扣失败轮 |
| 会话过期 / 轮数用尽后继续分析 | 执行前确认新会话 | 新会话从第 1 轮起算 |

自然语言涉及对象范围变更时仍可能需要理解，算一次分析；从正式选择器直接改已知 ID 才属于免费筛选。新会话不得通过自动跳转静默创建或扣费。

### 15.2 免费筛选的边界

复用原语义查询特征，在完整合格集合重新检索，不只过滤当前 20 张。免费重查不再调用新的昂贵看图核对或生成追问；使用已有兼容核对缓存，或仅按语义相近排序。新候选没有核对缓存仍可展示通用“画面相近”提示。

查询特征同时保存文本编码器和空间版本。模型升级后若原特征不兼容，使用已保存的解析文本按当前空间重新编码，费用由平台承担，不计用户新轮，也不重做描述理解或候选核对；成功后生成新查询版本。无法完成兼容重编码时提示暂不可刷新并保留记录，不混用向量，也不要求用户为系统升级付费重开。

删除 / 新增画面偏好会改变语义特征，必须走明确标价的“重新分析 · 使用 1 轮”。免费重查依旧有服务端频率和资源上限，不能无限并发。

### 15.3 幂等与结算

请求先预占，只有服务端成功提交可恢复的有效结果后才结算。正常零结果是有效检索，系统故障造成的空结果不是。

相同请求 ID、重复点击、网络重试只能结算一次；模型多次尝试不等于多个用户分析轮。失败 / 最终超时释放预占，迟到结果按第 8.4 节处理。客户端超时但服务端已在截止前成功，恢复原结果与原扣费记录。

会话删除不退还已正常使用的次数。用户计次和实际供应商费用独立；失败供应商调用仍可能产生费用，平台日志如实记录。

### 15.4 成本口径

- 建库：图片读取、首次编码、存储及必要的模型版本重建。
- 在线：描述理解、文字编码、检索基础设施、触发时的候选核对及重试。
- 可选：标记 / OCR 生成及额外抽检工具调用，单独预算。
- 原每月 2,000 元云费用假设不自动包含新增模型费用；最终测算使用选定模型单价与真实调用量。

同图同模型复用计算、仅变化图片重算、限制候选核对、历史任务低优先级、关闭无收益增强，是本版主要成本控制手段。上线前不承诺未经验证的命中率或固定单次成本。

索引写入、人工附属修正及生效事件可靠记录；源数据发生变化时返回过期 / 冲突，不自动覆盖。按消费者可靠投递，覆盖历史补建和实时新增，避免仅靠每日全量扫描维持同步。

## 17. 历史补建、试点与上线指标

### 17.1 历史补建

1. 盘点当前可公开卡及有效正背面，区分缺图、无背面、错误链接和已有索引。
2. 用代表性小卡与中文描述完成模型效果验证，再创建受预算控制的补建批次。
3. 自动计算图片向量并入库，不要求人工逐卡打标；与正式关键词检索并行。
4. 正常在线请求及新卡任务优先；支持暂停、取消、失败重试和断点续跑。
5. 批次运行中发生换图、下架、删除时，以当前版本为准，旧快照不能复活。
6. 记录覆盖、费用和失败类型；达到试点目标后逐步扩大图鉴与用户范围。

正面有效覆盖率以可公开且有有效正面的小卡为分母；背面以实际有有效背面的图片数为分母。人工标记数量不作为覆盖率或上线门槛。

尚无索引的卡可按正式关键词出现，但不保证按画面找到。低覆盖范围提示“部分小卡正在完善检索”；不得要求用户重新提交已有卡来修复索引问题。

### 17.2 评测与监控

| 指标 | 口径 |
| --- | --- |
| Top 5 / Top 20 命中 | 有人工确定目标且目标在当前图鉴的固定样本，前 K 个是否含可接受目标 |
| 正式条件违反率 | 返回卡不满足已应用正式 ID / 权限 / 状态条件的比例，功能验收要求为零 |
| 无目标误导 | 无目标样本是否被宣称“已找到 / 确认匹配”；首期仅相近推荐 |
| 用户明确找到比例 | 有“就是这张”的有效会话 / 有效会话，不能代表全部真实成功率 |
| 零结果 / 核心失败 | 分别统计，候选核对失败再单独记录 |
| 索引覆盖 / 积压 | 有效当前版本比例、排队时长、阶段失败及重试成功 |
| 时延与成本 | 分步骤 P50 / P95、每有效会话、每千张图片建库费用 |
| 人工成本 | 抽检数量、有效问题量、平均处理时间、重复问题合并量 |

固定评测比较“基础图文检索”“加候选核对”“加可选标记”三种配置，用命中、时延和费用决定增强开关。不能仅凭模型自己判定“更相关”证明升级有效。

上线前由产品和研发确认评测集、数据量 / 并发、Top-K 门槛及预算；文档中的功能验收完成不等同于已经通过线上效果验收。

| 结构化重查目标 | 同约定规模下 P95 ≤ 2 秒 |
| 可选标记 / OCR | 首发默认关闭，不影响核心检索 |

性能为待压测目标，尚未验证。超过 2 秒给用户处理反馈；候选核对可提前超时降级，不能为了等待增强步骤耗尽全部响应时间。

### 18.2 数据与可用性

- 首次与分页返回都验证最新发布状态、正式范围和访问权限；异步索引延迟不能扩大可见范围。
- 换图后旧语义结果失效，正式关键词查询仍按当前主资料进行；图片索引尚未就绪时不能拿旧图分数解释新图。
- 请求频率、输入长度、单会话并发、候选规模和模型输出大小由服务端限制。
- 用户原文只在受控存储保留；可读历史、模型日志与样本导出使用一致的删除 / 保留规则。删除后的备份清理周期在上线技术方案中落实，费用审计不无限保留完整原文。
- 供应商只收到完成能力必要的图鉴图片、描述和匿名请求标识，不传手机号、账号凭证和完整拥有清单。私有备注不进入公共索引。
- 禁用找卡 AI 时，原图鉴录入、扫描、普通搜索和收藏功能仍可独立使用。

## 20. 交付顺序、评审项与依据

### 20.1 建议交付

| 阶段 | 内容 | 完成条件 |
| --- | --- | --- |
| 核心建库 | 图文模型验证、正背面索引、实时事件、后台状态与重试 | 无标签也可按描述查到真实 Card ID，生命周期同步正确 |
| App 闭环 | 初始 / 结果 / 条件 / 追问 / 历史 / 质量反馈、额度幂等 | 核心验收场景通过，固定样本可复现 |
| 小范围试点 | 指定用户与图库、按需候选核对、质量抽检和预算 | 达到约定效果、时延及成本门槛 |
| 扩大覆盖 | 历史补建、优化路由、按需启用辅助标记 | 增强收益有评测依据，可单独关闭与回滚 |

核心可用性不依赖可选标记模块的完成。模型核对与额外识别调用须证明收益后放量，避免用更多调用替代检索基础质量。

### 20.2 待评审参数

需要在实施前确定：免费 / 会员月会话额度、图文模型与部署方式、供应商实际费用、试点范围及评测门槛、索引刷新时效与运行并发、抽检预算、原文删除及备份周期。

已确定的产品方向：自动图文检索为主，视觉偏好排序，正式资料精确筛选，原图鉴审核保留，运营只处理抽检与问题，可选标签不构成审核或搜索前置。
