# 用户小卡与图鉴反馈需求补全（App / 平台）

版本：V0.2（按入口、分模块处理及贡献展示补全）

日期：2026-10-14

范围：需求文档；本稿不代表功能已实现。

## 1. 目标与范围

形成用户提交、平台审核、内容更新、结果回传的完整闭环，覆盖以下两种场景：

| 场景 | 用户诉求 | 平台处理位置 | 最终产出 |
| --- | --- | --- | --- |
| A：扫描后图鉴缺少小卡图片 | AI 扫描后未找到对应图鉴图片，提交小卡供平台补充 | 图鉴内容管理 → 小卡缺失收录 | 快捷新建小卡；关联提交用户 |
| B：已有图鉴数据错误 | 小卡、专辑或其他图鉴数据存在问题，按字段提交更正建议 | 图鉴内容管理 → 图鉴问题纠错（独立模块） | 更新对应对象的字段，并向提交用户同步处理结果 |

“未识别”不直接等于“图鉴缺失”：平台审核应先确认是否已存在对应小卡，区分识别匹配问题、图片缺失和整张小卡缺失。

## 2. 现状与补充点

根据提供的两张后台截图：图片编辑已有正反面图片、来源类型、版权状态、必填来源链接等字段；“图鉴审核与质量”已有反馈审核列表，展示类型、状态、关联对象和查看操作。

结合当前项目文件的初步核对：

- 已有扫描主动反馈、扫描反馈历史和后台扫描审核操作，可沿用并补全。
- 图片来源类型已有“用户提交”，需要补充图片版本身份和提交用户关联，不能仅增加一个来源选项。
- 部分图鉴详情的“反馈问题”入口目前仅提示，尚未形成完整的按字段纠错流程。
- 本次需补充统一反馈记录、字段纠错表单、平台处理详情、发布后的状态回传及用户通知。

上述为局部核对结果，实施前仍需核对各对象的字段配置和现有接口覆盖范围。

## 3. 统一业务口径

### 3.1 三类状态分开管理

| 维度 | 含义 | 建议值 |
| --- | --- | --- |
| 反馈处理状态 | 运营是否开始或完成处理 | 待处理、处理中、已处理 |
| 收录结果 | 用户提交的图片或建议是否进入已发布图鉴 | 待确认、已收录、未收录 |
| 图片版本状态 | 图片版本在平台中的身份 | 沿用现有枚举，新增“用户提交”；转为官方图鉴版本后保留提交来源 |

图片版本状态与专辑的发行版本、图片来源类型、版权状态、发布状态分别管理。“转官方”指进入平台维护的正式图鉴，不表示图片来源变成官方来源，也不自动代表图片已授权。

### 3.2 App 展示规则

| 平台处理状态 / 结果 | 场景 A 展示 | 场景 B 展示 | 用户可见内容 |
| --- | --- | --- | --- |
| 待处理 / 待确认 | 待处理 | 待处理 | 已收到反馈 |
| 处理中 / 待确认 | 处理中 | 处理中 | 正在核实 |
| 已处理 / 待确认 | 已处理 | 已处理 | 已完成审核，待发布；可显示公开说明 |
| 已处理 / 已收录 | 已收录 | 已收录 | 已发布内容入口及处理说明 |
| 已处理 / 未收录 | 未收录 | 已处理 | 场景 A 必须显示未收录原因；场景 B 显示未采纳或无需修改的原因 |

场景 B 按用户要求保留“已处理、已收录”两个结果标签；未采纳反馈以“已处理”展示，并明确说明“本次建议未采纳”，不让用户误认为数据已修改。待处理、处理中用于提交后跟进。

状态路径：待处理 → 处理中 → 已处理 → 已收录；无需采纳时直接完成处理并记录未收录结果。审核接受、创建草稿、保存修改均不能直接视为已收录。

## 4. 场景 A：扫描后反馈缺少小卡图片

### 4.1 App 入口与流程

1. 在 AI 扫描结果的单张小卡区域提供“未找到对应小卡？提交反馈”入口；多卡扫描按当前检测对象提交。
2. 自动携带扫描会话、检测对象、原图、当前裁剪图、裁剪区域、候选匹配结果及已选组合/艺人信息。
3. 展示图片预览，允许调整裁剪或更换图片；可补充背面图片、已知小卡信息和备注。
4. 用户确认提交后显示成功提示和反馈编号，提供“查看反馈进度”；返回扫描结果时保留原列表、选择和滚动位置。
5. 在“我的反馈”中查看图片、提交时间、处理状态、处理说明及收录后的图鉴入口。

### 4.2 提交字段

| 字段 | 规则 |
| --- | --- |
| 正面图片 | 必填；默认使用当前检测对象的裁剪图，原图和裁剪信息作为审核上下文保留 |
| 背面图片 | 默认选填；勾选双面小卡后必填，与后台正反面完整性规则一致 |
| 所属组合 | 必填；扫描有候选时带入供用户确认，切换组合清空不再有效的艺人、来源和版本 |
| 所属艺人 / 团体属性 | 单人小卡必填艺人，按所选组合过滤；选择团体小卡后免选单个艺人，沿用后台团体小卡逻辑 |
| 来源类型与来源对象 | 必填；类型为专辑、活动、其他来源；对象按组合/艺人筛选，切换来源清空版本。没有对应对象时填写缺失来源名称，运营补建后发布 |
| 小卡名称、来源版本及其他属性 | 暂按选填；小卡名称可由艺人与来源生成，平台发布前补齐必要信息 |
| 备注 | 选填，描述获取渠道、卡片特征或其他线索 |
| 来源链接 | 选填；用户提交图片不要求填写来源链接 |
| 提交用户、提交时间、反馈编号 | 服务端自动记录，用户不可修改 |

### 4.3 平台审核

新增独立“小卡缺失收录”模块，承接 AI 扫描发起的缺失小卡反馈；与“图鉴问题纠错”分开导航、列表、处理动作和发布目标。详情展示正反面图片、原图与裁剪信息、候选结果、用户填写内容、提交用户及处理记录。

平台可执行：

- **匹配已有小卡**：确认图鉴已有内容，关联目标小卡；说明是识别问题还是重复提交。未采用图片时不标记图片已收录，可向用户提供已有图鉴入口。
- **确认缺失**：以新增小卡为主路径；若核查发现已有同一小卡，则关联已有内容并说明，避免重复创建。已有对象图片更正走图鉴问题纠错流程。
- **一键转图鉴**：创建关联反馈的小卡草稿，自动带入组合、艺人/团体属性、来源类型、来源对象、版本、正反面图片、名称和提交用户；在当前审核详情的快捷录入区确认或修改，避免重新走完整录入步骤。缺失来源可暂存草稿，必须补建正式来源后才能发布。
- **保存草稿 / 发布小卡并收录**：快捷录入允许暂存不完整资料；正式发布执行现有新增小卡校验，校验名称、归属、来源、条件必填图片与图片使用状态。草稿与反馈一对一防重复，同一反馈重复点击转图鉴只能返回原草稿。
- **未收录**：填写必填原因后完成处理；禁止无原因关闭、驳回或忽略用户反馈。

建议未收录原因：已有对应内容、图片不清晰、资料不足无法确认、不属于收录范围、图片不符合使用要求、其他。选择“其他”必须补充文字，面向用户的说明应具体可理解。

### 4.4 来源链接与图片转官方

- 正面和背面分别校验来源类型：来源为“用户提交”时，来源链接取消必填；其他来源继续沿用现有规则。
- 无来源链接的用户图片允许进入审核、保存草稿及按用户提交规则发布，服务端与平台表单保持一致。
- 首次接收时，图片版本状态为“用户提交”。图片转为平台正式图鉴版本需执行明确的审核/发布操作。
- 转官方后必须保留提交用户 ID、反馈 ID、原图片版本 ID、转换人和转换时间；不得因修改版本状态而丢失来源链路。
- 来源类型仍保留真实的“用户提交”；版权状态单独审核，不自动改为“已授权”。
- 正式发布成功，且采用的图片已可在 App 图鉴中访问后，反馈结果更新为“已收录”。仅生成草稿时显示“已处理”。
- 多名用户提交同一卡片时，每条反馈分别保留；最终图片版本支持关联多个反馈，明确哪一条图片实际被采用。

## 5. 场景 B：图鉴数据纠错

### 5.1 App 入口与对象选择

组合、艺人、小卡、专辑及其他图鉴详情提供“信息有误？反馈更正”入口。从正在查看的详情进入时自动带入对象类型、稳定 ID、名称、缩略图及当前界面字段和值，不要求用户再次选对象。默认收起对象选择器，点击“切换反馈对象”后可搜索并切换其他已发布对象；切换后清空旧对象的字段建议，重新加载新对象字段。

对象必须以类型和稳定 ID 关联，不能仅依赖名称。支持小卡、专辑、组合、艺人等已有图鉴对象的数据错误反馈；专辑版本、公司、活动及其他来源按其图鉴详情字段开放反馈。

### 5.2 自动获取字段及填写流程

1. 选定对象后，自动获取当前参考详情页可见且允许反馈的字段，包括字段名称、当前值、字段类型和可选项。
2. 用户选择一个或多个问题字段，每个字段展示“当前值”和“建议更正为”。
3. 根据字段类型填写建议值：文本输入、日期选择、枚举选择、关联对象搜索、多选或图片上传。
4. 用户填写问题说明/备注，可补充证明图片或参考链接；预览后提交。
5. 提交后进入“我的反馈”，显示对象、问题字段、处理进度和公开处理说明。

字段清单由对象类型和 App 详情字段配置生成，服务端校验允许反馈范围；不把内部 ID、权限、运营备注等内部字段暴露为可选项。

### 5.3 表单规则与字段示例

| 对象 | 建议可反馈字段示例 |
| --- | --- |
| 小卡 | 名称、组合、艺人、所属专辑/活动/其他来源、所属版本、正面图片、背面图片、详情页可见属性 |
| 专辑 | 名称、封面、所属组合/艺人、发行日期、发行版本及详情页可见信息 |
| 其他对象 | 以实际详情页字段为准，如名称、图片、介绍、关联信息及日期 |

- 每条反馈只对应一个数据对象，可包含多个字段；切换对象时提示确认清空已有字段建议。
- 至少选择一个字段；每个字段必须填写建议值或明确选择“应为空/应删除”。“未知正确值”允许只描述问题，但问题说明必填。
- 若建议值与当前值相同，提示用户调整；仅描述问题时不要求猜测正确值。
- 备注独立保存，不能代替所有结构化字段；附件和参考链接选填。
- 保存提交时的当前值快照与对象版本，后续图鉴变化不覆盖用户原始反馈。
- 支持上传图片：选择头像、封面、正面图片、背面图片等图片字段时，可上传建议更正图片；此外可独立上传截图或证明图片作为附件。平台审核与用户反馈详情均可查看图片，采纳后按对应对象的图片发布规则更新。
- 数量、字数、图片格式和大小限制优先沿用现有 App 上传规范；具体参数在接口设计时确定并在页面明确展示。

### 5.4 平台新增处理能力

新增独立“图鉴问题纠错”模块，仅更新已有图鉴对象，不提供新建小卡动作。支持筛选对象类型、处理状态、收录结果、提交时间和处理人。列表展示反馈编号、对象名称、字段摘要、提交用户、提交时间、状态和操作入口。

审核详情按字段并排展示：

| 字段 | 提交时当前值 | 用户建议值 | 平台最新值 | 审核后采用值 | 处理结果 |
| --- | --- | --- | --- | --- | --- |
| 示例：专辑名称 | 原名称快照 | 用户填写名称 | 实时读取名称 | 运营确认后的名称 | 采纳 / 部分采纳 / 未采纳 |

运营可逐字段采纳、修改后采纳或不采纳；不采纳需填写公开原因。支持独立的内部备注和面向用户的处理说明，内部备注不回传 App。

- 保存处理意见不立即覆盖正式数据；运营确认后按现有对象编辑、校验、审核发布规则生效。
- 提交时与当前值不同，提示数据已变化，运营重新核对；禁止直接覆盖其他人最新修改。
- 同一次发布涉及多个字段时，校验失败整次更新回滚，反馈不标记已收录。
- 全部不采纳或无需修改：状态为已处理，回传明确原因。
- 全部或部分采纳并成功发布：状态为已收录；部分采纳时展示采用字段、未采用字段及原因。
- 若当前数据已被其他反馈修正，关联已生效版本并说明“问题已修正”；不能伪造本次反馈的采用记录。

## 6. 统一反馈中心与客户端同步

### 6.1 App“我的反馈”

建议将现有“我的扫描反馈”扩展为“我的反馈”，提供“全部 / 扫描缺失 / 数据纠错”筛选；两类反馈的进度统一在 AI 扫描 → 我的反馈中查看；我的贡献仅展示已收录小卡，不提供查看进度入口。

列表显示图片或对象缩略图、反馈类型、对象名称、状态、提交时间；详情展示原始提交内容、最近更新时间、公开处理说明、状态时间线和已收录内容入口。用户只能查看自己的反馈。

### 6.2 同步规则

- 平台是反馈状态的唯一数据来源，App 通过接口刷新列表及详情；进入页面、下拉刷新和通知跳转时获取最新状态。
- 状态变为“已处理”“已收录”或场景 A“未收录”时，向提交用户发送站内消息；系统推送按现有通知能力和用户设置接入。
- 消息包含反馈编号、对象摘要、最新结果和公开说明，并跳转反馈详情。
- 消息发送失败不撤销业务结果，记录失败并重试；同一反馈、同一状态版本避免重复通知。
- 状态写入和结果记录保持一致，不能先通知已收录再发布内容；发布失败保留已处理并记录内部失败原因。
- 正式内容后续下架时保留历史收录事实，目标入口提示当前不可用，不删除用户反馈记录。

本稿将“同步到客户”暂按“同步到提交用户的 App 客户端”理解；如指独立客户系统，需要另补同步目标、字段及接口。

### 6.3 小卡详情：贡献来源

- 用户提交的小卡成功收录后，小卡详情新增“贡献来源：用户名”。用户名是超链接，点击进入对应用户主页。
- 贡献关联使用稳定用户 ID，展示用户当前昵称；图片来源类型和版权状态分别展示，不因贡献署名而改为官方来源或已授权。
- 仅建立真实采用的贡献关联；重复反馈但未采用图片、不采纳记录不能凭审核完成生成贡献。
- 支持多名实际贡献用户时分别保留关联，按贡献时间展示。昵称变化不影响关联，主页不可访问时降级为不可点击名称。

### 6.4 我的主页：我的贡献（仅小卡）

- 在现有“已拥有、心愿单、卡册”页签后新增“我的贡献”；进入他人主页时对应显示“TA 的贡献”。
- 展示已正式收录且关联当前用户的小卡，卡片包含正面图、名称与收录时间，点击进入小卡详情。
- 待处理、处理中、已处理待发布和未收录的记录不计入贡献，统一在 AI 扫描 → 我的反馈中查看；我的贡献不展示“查看进度”或待处理入口。
- 组合、艺人、专辑等信息纠错不计入本页。小卡纠错是否构成贡献暂按“采用用户图片才新增真实图片贡献”处理；文字纠错不默认增加小卡贡献。
- 贡献按小卡 ID 去重；同一卡多次提供图片不重复计算贡献张数。列表支持分页和空态。
- 内容下架后不再展示可公开访问的贡献卡片，内部贡献历史保留；贡献者主页展示沿用现有用户可见性规则。

## 7. 数据与接口需求（逻辑定义）

优先扩展现有扫描反馈、图鉴反馈及审核能力；以下是逻辑要求，最终表结构和路由沿用项目规范设计。

| 数据组 | 必需信息 |
| --- | --- |
| 反馈主记录 | 反馈 ID、类型、提交用户 ID、对象类型/ID、提交时间、更新时间、处理状态、收录结果、公开说明、内部备注、处理人 |
| 扫描上下文 | 会话 ID、检测对象 ID、原图引用、裁剪图引用、裁剪区域、候选及用户补充信息 |
| 纠错明细 | 字段键/名称、字段类型、原值快照、建议值、问题说明、逐字段审核结果、采用值、未采用原因 |
| 图片来源关联 | 图片版本 ID、用户提交版本身份、真实来源类型、可空来源链接、提交用户 ID、反馈 ID、转官方记录 |
| 小卡贡献关系 | 小卡 ID、用户 ID、反馈 ID、采用图片版本 ID、贡献类型、收录时间；支持去重及按用户查询 |
| 生效与审计 | 对象版本、发布记录、最终关联对象/图片、操作者、状态变更记录、通知记录 |

需支持的接口能力：

1. 获取可反馈对象及其可见、可反馈字段和当前值。
2. 提交扫描缺失反馈、提交字段纠错反馈，校验登录用户及对象/字段有效性。
3. 获取当前用户反馈列表、详情和状态历史。
4. 平台获取反馈列表/详情、开始处理、保存审核意见、关联对象、新建草稿、拒绝收录及确认发布。
5. 发布成功后更新关联反馈结果，产生通知事件；失败支持重试且不重复创建内容。

提交用户 ID 由登录身份获取，不接受客户端自行指定；正式内容只能由具备权限的运营审核和发布。所有处理行为留痕，重复点击提交或发布需具有防重复机制。

## 9. 验收标准

1. 单卡及多卡扫描均可针对当前检测对象提交缺失反馈，后台查看到正确图片、裁剪上下文和提交用户。
2. 用户提交图片无来源链接时，可提交、保存并按对应规则审核发布；非用户来源仍遵守原来源链接校验。
3. 用户图片进入平台后具有“用户提交”版本身份，转正式图鉴后仍能追溯到提交用户及反馈。
4. 创建草稿或审核接受后仅显示已处理；正式发布且图片可访问后显示已收录。
5. 场景 A 未收录必须填写原因，App 展示同一原因；“忽略”不能绕过原因要求。
6. 从小卡或专辑详情进入纠错时对象自动带入，字段来自当前详情配置，选择后显示当前值并支持对应类型输入。
7. 一条纠错可含多个字段，提交快照保留；运营可逐字段采纳或拒绝，用户可查看部分采纳的具体结果。
8. 对象发生并发修改时提示冲突；发布校验失败不写入半成品、不显示已收录、不发送收录成功通知。
9. 两类反馈的后台状态与 App 列表、详情、消息一致；用户无法读取其他人的反馈或内部备注。
10. 重复提交请求、重复发布或通知重试不会生成重复内容或同一状态的重复消息。
11. 已有对应小卡、对象被删除/下架、图片失效等情况均有可理解的处理说明，原始反馈和审计记录保留。

12. 从详情点击纠错时对象和值自动带入，默认无需再次选择；切换对象后字段和值正确刷新，不携带旧建议。
13. 缺失小卡校验组合、单人艺人/团体属性、来源类型和对象，组合与来源切换会清空失效关联；双面小卡必须有背面。
14. 两个平台模块数据和动作分离；缺失收录能一键生成预填草稿，纠错模块只能更新已存在的对象。
15. 一键转图鉴不会直接显示已收录；成功新增并发布后小卡详情出现可点击贡献来源，进入正确用户主页。
16. 我的贡献只展示当前用户已收录小卡，文字纠错、未发布草稿和未收录反馈不计入；重复请求不产生重复小卡或重复贡献。

## 10. 待评审确认

以下暂按本文建议执行，可在调整稿时修改：

- “用户提交”作为图片版本身份独立于来源类型；现有图片版本枚举和转官方操作名称需实施前核对。
- 场景 B 未采纳显示“已处理 + 未采纳原因”；部分采纳发布后显示“已收录 + 字段明细”。
- 组合、艺人、小卡、专辑均支持纠错及图片上传；需进一步确认其他对象的开放顺序和各详情页允许反馈的具体字段清单。
- 已有小卡匹配成功但未采用用户图片时，显示已处理并提供已有图鉴入口，是否另增加“已有收录”提示。
- 小卡详情公开展示贡献来源用户名并链接用户主页；用户 ID 与内部审核信息不公开。账号注销、主页不可访问等情况显示不可点击的占位名称，保留内部贡献关联。
- “同步到客户”是否仅指 App 客户端；是否需要独立客户系统同步。
- 附件数量、字段数量、文本长度和通知渠道的具体限制与现有能力对齐。
