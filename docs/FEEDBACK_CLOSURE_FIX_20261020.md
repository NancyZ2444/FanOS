## 闭环规则

1. 用户 AI 扫描未匹配到小卡，选择检测卡面提交缺失反馈；扫描原图、检测区域和提交资料保留。
2. 运营可多次保存内部草稿。保存不会把卡片发布为官方图鉴，也不向用户发送处理更新。
3. **已采用**：通过来源、图片可访问性及图片使用授权校验后发布。采用的用户图片记录保留提交来源，并登记为官方图鉴图片，关联贡献记录；用户可进入正式图鉴。
4. **无法采用**：结束本次审核，保留用户提交图片、说明和处理记录，不删除该反馈。
5. **信息缺失待补充**：说明具体缺失内容，用户在原记录内补充后重提。重提保留此前提交快照和处理历史；复用原内部小卡草稿，新提交图片需要重新确认使用授权。
6. 重复点击 / 网络重试复用幂等请求编号；同一编号不同内容、过期 revision、越权用户及非待补充状态均拒绝。

用户主动重提会产生“已补充信息，等待重新审核”的提交记录，但不会向本人重复发送运营结果通知。

接口增量：

- 运营操作 `/api/v1/admin/console/feedback/{id}/actions` 增加 `action=need_info`。
- 用户 `POST /api/v1/feedback/records/{id}/resubmit`，复用提交表单并带 `revision`、`request_key`。
- 反馈读取增加 `can_resubmit`；结果增加 `NEEDS_INFO`。原提交、审核和公开图鉴接口保持兼容。

## 本地操作顺序

1. 刷新后台目标反馈页面，进入编辑；正式来源尚未建立时留空，点“保存草稿”。App 原记录仍显示待处理，没有新的结果通知。
2. 在“更多 → 信息缺失待补充”填写具体说明并确认。App 打开该反馈，点“补充信息并重新提交”，修改图片 / 来源 / 说明后提交。
3. 后台刷新原记录，确认补充资料，选择正确的正式来源及版本、核实图片使用授权，填写公开说明并发布。
4. App 原记录显示已采用并可查看官方图鉴；若选择无法采用，则仍能查看提交记录及说明。

上述实际审核操作会更新用户真实记录；本次自动验收仅在隔离库 / 副本执行。
