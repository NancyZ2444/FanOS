# 图鉴新增提交失败修复（2026-10-29）

## 问题与根因

线上反馈 `fb_82df33eb31aa435ebd1583da94f1b382` 补充专辑信息后无法保存草稿或提交处理结果。排查时记录仍为 PENDING、revision=1，日志未收到对应 actions POST。

在实际线上地址的隔离浏览器中确认：`isSecureContext=false`，`crypto.randomUUID` 不可用，而 `crypto.getRandomValues` 可用。原表单在 try/finally 之前生成请求编号，抛错会阻断提交并可能使按钮持续加载。此问题发生在请求发出前，并非该反馈的专辑关联被后端拒绝。

## 修复范围

专用分支：`codex/catalog-addition-fix-20261029`。

- 增加公共 `createRequestKey()`，优先使用原生 UUID；HTTP 场景使用安全随机字节生成 UUID v4，不采用时间戳或固定值替代。
- 图鉴新增/缺失图鉴、反馈处理、组合艺人资料维护与登录续期统一复用。
- 生成编号及序列化纳入错误处理，失败提示可见、解除加载状态并保留填写内容。
- 相同内容和版本重试沿用原编号；修改内容才生成新编号；401 刷新后重放原业务请求。
- 后端接口、业务校验、数据库结构及反馈审核状态不变。本次不替用户采纳或发布该条反馈。
