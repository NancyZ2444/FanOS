## 后台变化

### 组合与艺人内部资料

内部维护表单使用“内部备注（选填）”，保存和发布无需公开修订说明。实际资料发布仍会更新 App；修改差异、操作人与备注保留在管理员修订存档中。

用户反馈产生的公开修订继续要求公开处理说明。公开历史接口仅返回用户反馈修订，不返回平台内部或初始化存档；管理员使用独立历史接口查看完整存档。既有内部历史按来源过滤，无需删除或迁移。

### 相似小卡提醒

- 新增/编辑小卡上传正面图片后检查相似图鉴；图鉴新增反馈审核也使用相同提醒组件。
- 提醒展示已有小卡缩略图、名称、相似度与状态，点击可在新页打开已有记录。
- 保存、提交或发布前重新检查；发现相似卡时需明确确认“已核对，继续”。取消后保留输入，便于改为维护已有卡。
- 列表单条、批量发布也进入查重确认，避免绕过编辑页提醒。
- 导入预览支持逐行“核对相似卡”；导入完成可打开对应草稿继续核对。外部链接须先导入平台存储才能执行图片比对。
- 编辑已有卡时排除自身 ID，草稿卡也纳入比对。没有自动合并、覆盖或删除已有卡。

新增只读接口 `POST /api/v1/admin/console/cards/similar`，请求为 `image_url`、可选 `exclude_card_id`。复用现有 `CardMatcherAdapter` 和匹配状态判定，仅读取平台管理的图片；不为查询创建卡片、上传文件或识别任务。

相似度用于辅助人工核对，不能保证两个相似卡属于同一版本。图片不可用、细节不足、比对失败或已有图鉴缺少可用图片时会提示检查未完成，不显示成“没有重复”。

## App 变化

| 页面 | 更新内容 |
| --- | --- |
| AI 扫描反馈图片 | 正面、背面预览统一为 55:85；点击图片更换，移除“更换正面/更换背面”文字按钮；保留单独裁剪入口。 |
| 上传与裁剪 | 选择图片后进入固定 55:85 的裁剪；支持拖动、缩放、重置；取消不覆盖上一张图片。裁剪坐标按原图像素比例计算，横图、方图也保持固定卡片比例。 |
| 扫描结果收起状态 | 无精准匹配但有真实候选时，横向展示候选缩略图与相似度，点击进入图鉴详情。 |
| 扫描结果展开状态 | 展示候选卡片和基础信息，保留选择、确认及反馈；无候选时不伪造推荐卡或相似度。 |
| 每日翻卡 | 使用本次提供的 Fan OS 紫色图片作为默认背面，三张卡尺寸一致，翻开前后维持 55:85。 |
| 通知 | 分为“公告 / 通知 / 反馈结果”，默认显示通知；右上角与标题同行放置刷新按钮；移除“我的反馈”入口，反馈结果仍可进入具体反馈详情。 |

通知分类在服务端查询数量限制之前完成，避免大量反馈消息挤掉普通通知。公告使用现有已发布公告接口；普通通知与反馈结果使用 `/notifications/inbox?category=NOTIFICATION` 和 `FEEDBACK_RESULT`。保留已有已读、跳转与通知设置能力。

## 默认卡图与数据兼容

用户提供的原图未修改，分别存放于：

- `apps/admin/public/images/default-card-back.png`
- `apps/mobile/assets/cards/default-card-back.png`

后台公共 `CardArt` 在图片缺失或加载失败时展示默认图，并标注待上传或加载失败。默认图仅作 UI 占位，不写入真实小卡正反面字段，不绕过必填图片校验。

本次无需业务数据库迁移。没有自动采纳/发布真实反馈、合并重复卡或修改现有图鉴图片。API 回归使用独立测试数据库；模拟器联调未执行每日翻卡抽取、反馈提交或消息已读操作。
