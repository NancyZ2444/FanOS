# 小卡图片选择、上传识别与公司导入

更新日期：2026-10-11。

本次补齐三项后台操作：小卡的组合 / 艺人图片展示、上传卡图识别并维护记录、公司 CSV / Excel 批量导入。沿用已有图鉴记录、权限和审核规则。

## 组合与艺人图片

新增小卡的组合和艺人选择卡片、下拉候选及已选值显示对应档案图片。优先使用图鉴 `image_url`，兼容已有 `cover_image` / `avatar_url`；无图片或加载失败时回退到名称首字。图片从组合 / 艺人管理维护，不自动生成或替换图片。组合筛选与历史成员规则保持原有逻辑。

## 上传识别与快速维护

入口：小卡管理 →「上传识别」。每次上传一张小卡正面，支持 JPG / PNG / WebP，最大 10 MB。上传会校验真实图片、处理方向并自动框选卡片区域，支持手动拖动四角调整；确认裁剪后才开始识别。检测到多张时可选择本次保留的一张。完整操作见 [裁剪说明](CATALOG_CARD_CROPPING_20261011.md)。

- 高相似度且结果唯一：自动打开已有小卡维护页，保留原记录 ID、图片与资料。
- 存在多个相似结果：展示卡图、名称、相似度和状态，由运营选择「维护记录」，或使用「未找到，手动新增」。
- 未匹配：自动进入新增小卡表单并带入上传卡图，手动选择组合、艺人、来源和专辑版本，补充信息后保存草稿。
- 若部分现有记录缺少可用卡图，新增页显示比对不完整提示。系统不会把识别服务异常当作未匹配；异常时可重新上传重试。

后台会比对所有状态的小卡，包含草稿、下架和归档记录。优先使用与当前图片地址相符的索引；未索引的托管图片在本次请求中计算特征，避免仅因草稿尚未进入公开索引而重复新增。不会下载任意外部 URL。缺图、不可读取或特征不足的记录计入未参与比对数量。

识别只定位候选，不替换已有图片、修改资料、自动发布或增加用户收藏。新卡仍需完成手动资料填写并保存；原有图片版权字段不会因上传识别而自动改成已授权。已发布 / 待审核记录继续按下架 / 驳回流程编辑，归档记录从归档列表维护。

识别采用已有真实卡图特征匹配引擎。高置信匹配阈值为 0.90，且领先次优结果至少 0.04；0.60 以上展示相似候选。识别结果受拍摄质量、画面内容及已有卡图覆盖率影响，不将相似度当作身份保证。上传图与识别结果有操作日志；实际保存时沿用小卡图源与图片历史机制。

## 公司批量导入

入口：公司管理 →「批量导入公司」，或批量导入页选择「公司」。支持下载 CSV / Excel 模板，最多 5 MB / 2,000 行。

| 字段 | 说明 |
| --- | --- |
| `name` | 必填公司名称，1–120 字符 |
| `description` | 可选描述，最多 2,000 字符 |

名称按大小写、全半角及多余空格归一后查重，包括现有归档公司。公司不要求组合 / 艺人字段；导入只创建公司档案，关联关系在组合 / 艺人资料页选择维护。导入后的公司可立即被选择。

支持预检、逐行错误定位、修正 / 跳过、再次预检、确认导入和历史任务。确认前重新查重；任一冲突整批回滚；已完成任务重复确认不重复创建。不会覆盖已有公司或改写历史公司关系。

## 数据与后续补齐

本次使用已有 JSON 运营记录和图片字段，无数据库结构迁移；未批量更改运营数据。无图片的组合 / 艺人需在档案上传图片，缺少卡图的历史小卡需补充托管正面图片才能参与识别。补齐图片后，下次后台识别即可使用，不需要重建卡片 ID。

接口：`POST /api/v1/admin/console/cards/recognize`（multipart `file`）；现有导入接口新增 `kind=companies`。仅图鉴编辑角色可识别、导入；普通用户和非图鉴运营角色不能写入。OpenAPI 已同步。
