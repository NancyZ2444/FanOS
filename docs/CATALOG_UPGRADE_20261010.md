## 本次功能

| 场景 | 已实现行为 |
| --- | --- |
| 组合、个人、合作发行 | 专辑、活动、合集、周边可关联多个组合或艺人；Solo 不再必须创建虚构组合。保留旧 `group_id`，参与艺人使用 ID。 |
| 历史归属 | 成员经历支持加入、退出、暂停、重新加入、主身份、职务、初始成员和排序。普通资料编辑不改写经历；历史卡按发行日期和历史关系校验，不按当前身份反推。 |
| 历史资料缺失 | 既有卡的组合、艺人、发行日期均未变时，可维护其他字段；缺失历史关系不使旧身份失效。新卡或变更归属仍须提供有效关系。 |
| 公司经历 | 公司主数据及组合 / 艺人的公司有效期关系；新旧经历分段维护，保留原公司文本。 |
| 活动 | 父子活动、关联专辑、开始 / 结束日期、城市、场馆、线上标记、业务状态和别名；阻止循环父子关系。 |
| 来源与版本 | 实体详情维护结构化版本及来源链，小卡关联发行版本 ID；来源链不能自指或成环，被引用版本不能删除。 |
| 工作台与创建 | 图鉴规模、状态、今日新增、待处理任务及最近操作；全局 Quick Add 和详情中的关联创建。小卡向导内新增来源时保留未保存内容。 |
| 详情与筛选 | 概览、历史成员、关联实体与小卡、素材、公司经历、社交账号 / 动态及变更历史；小卡档案含图片版本、来源、AI 索引、反馈。增加公司、年份、关联数据及小卡来源 / 版本筛选。 |
| 小卡批次 | 继承共享字段，按成员和数量生成草稿；图片、校验、发布进度，全部校验及发布合格卡。生成幂等，解除批次关系不删除小卡。 |
| 批量编辑 | 设置组合、艺人、来源、版本、Edition、类型、标签、官方 / 限定标记；先预览，再按更新时间重检并整批提交。变更来源时清除不适用的旧版本 ID。 |
| 图片批量上传 | 多文件手动指定小卡和正反面，逐张保存；失败时保留已完成部分，更换图片保留来源版本历史。 |
| 表格导入 | 原七类导入继续可用；增加组合 + 艺人联合导入、预览逐行修改和跳过。确认时重检，已完成任务不可改写，重复确认不重复创建。 |
| 审核与质量 | 用户纠错、缺失内容、扫描反馈和图鉴举报；展示当前值、建议值、证据及提交人。接受缺失内容先生成草稿；更新已发布目标时，校验失败整笔回滚。 |
| 人工合并 | 选择重复卡与目标，预览后迁移收藏数量、心愿单、卡册、扫描等引用；旧卡归档，旧详情 ID 跳转目标。存在未支持的社区关系时拒绝合并。 |
| AI Scan | Pending / Processing / Indexed / Failed / Disabled、失败原因和重试；有效索引必须匹配当前图片及引擎。下架卡保留识别，草稿 / 归档卡不进入匹配。 |
| 历史访问 | 下架卡保留收藏、心愿单、卡册及扫描关系；具有本人历史关系的登录用户可查看基础详情和下架提示，公开目录隐藏下架内容。 |

## 删除规则

从未发布的 Draft 可删除，其他业务引用仍须先解除。曾发布后下架、之后重新保存成 Draft，以及归档记录，须解除所有上下游关系。已发布、审核中、驳回记录不能直接物理删除；驳回记录可先保存为 Draft。

管理员先预检关联，再确认删除。没有下游引用的下架 / 归档来源或小卡，可明确确认解除上游后重新预检。成员、公司历史和合并旧 ID 的目标关系受保护。批量删除任一记录不满足条件则整批回滚。完整规则见 [删除说明](CATALOG_DELETION.md)。

## 数据结构与兼容

- 保留现有实体 ID、收藏数量、心愿单、卡册、图片历史及操作日志。
- `f310_catalog_operations` 接在 `e2a10b8f4c63` 后：五类内容的 `group_id` 可空，新增 `catalog_operational_records`。当前工程 head 为 `b610_profile_background`，已包含图鉴迁移；本次不改写其他模块迁移。
- 扩展记录 `kind`：`versions`、`sources`、`batches`、`reviews`、`companies`、`company_relations`、`memberships`、`import_input`。所属实体使用 `entity_type / entity_id`，内容存入 `data`；成员记录同步既有 `group_memberships`，不重建成员 ID。
- 原组合 ID、来源名称及版本文本继续保留。唯一、同组合的旧来源名称匹配仅用于后台展示兼容；多义或找不到的来源不猜测关联。
- 启动脚本默认 `AUTO_SEED=false`，避免重复演示初始化改写已有资料。全新演示库需显式指定 `AUTO_SEED=true`。
- 索引仍使用现有图片特征 JSON 文件和单 Worker，不另建 AI 卡库。生成成功后替换索引文件，失败保留旧文件；旧图片索引不会被标为新图片的有效索引。

## 数据升级执行顺序

1. 暂停相关写入，备份数据库、素材和索引；导出实体 ID、原字段、拟补字段及依据，保留只读快照。
2. 仅执行兼容结构升级，检查结构、行数、ID 集合和内容指纹，恢复正常运行。
3. 先补发行实体的艺人 ID 关系，再确认 7 张卡的来源映射；只更新目标 ID 的扩展字段，不重建卡，不迁移 Owned / Wishlist。
4. 确认来源后补版本记录和版本 ID；成员、公司历史另行按证据补有效期。当前身份变化只改变当前展示，不改变历史归属。
5. 每批校验并留审计，核对公开图鉴、历史详情、收藏数量、卡册和扫描。未确认项保留原数据与质量提示，不阻塞历史访问。

**本次没有执行语义回填、数据合并或用户关系迁移，只返回补齐策略。** 人工合并仅在管理员明确预览确认后修改指定记录。

## 范围边界

按要求不做建议增强项：AI 辅助创建、URL 内容导入、智能图片匹配、AI 重复识别、Find & Replace、自动回滚、定时发布、可信贡献者、额外角色扩展。结构化版本与历史关系属于前台数据契约，本次落实必要关系不代表交付建议增强项。

未重新开发 Flutter 页面或产出移动端安装包，未增加 AR 播放器、外部授权服务或生产向量数据库。后台仍使用现有整体目录加载和前端分页，未验证万级目录及 PostgreSQL 并发；这是当前容量边界，不影响本次小规模数据验证结论。

入口与操作见 [后台 README](../apps/admin/README.md)，测试记录见 [VERIFICATION.md](VERIFICATION.md)。
