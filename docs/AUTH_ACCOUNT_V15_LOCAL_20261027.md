# 账号与认证 V1.5：本地交付与验证

范围：依据 2026-10-26 V1.5 需求更新第一阶段账号服务、现有后台及 Flutter App。仅更新本地 API、管理平台及 iOS 模拟器；未发布云端、未提交 Git、未打 Android 包。拼团和游戏不在本轮启用范围。

## 账号与数据边界

- App 用户、后台管理员、登录白名单分别存储。App 手机号和旧验证码不再作为后台登录方式。
- App 与后台令牌有不同 audience，均关联可撤销的服务端会话。旧版无会话令牌失效，需要重新登录。
- 新增 `auth_*` 表，不重建、不删除原 App 用户；已有用户 ID、小卡、收藏与卡册不迁移到新账号。
- 本地更新前 SQLite 一致性备份：`output/auth-v15-20261027/backups/fan_os-before-auth-v15.db`。备份权限为 0600，且位于 Git 忽略目录。备份时用户 4、小卡 14、卡册 11；`PRAGMA quick_check` 为 `ok`。
- 白名单只建配置，验证成功才创建新 App 用户；新用户 ID 不由手机号生成。已有手机号登录仍使用原用户 ID。
- 未确认的敏感操作角色映射采用保守策略：仅最高管理员可配置测试码、管理白名单、查看完整手机号、解绑、封禁及管理后台账号。服务端校验，不只依赖前端隐藏。

## 主要变化

### App

- 手机号、验证码同页流程，独立发送与登录状态，协议勾选，6 位验证码与倒计时；白名单模式不展示实际验证码。
- 账号安全入口：身份状态、手机号变更、关联/解绑；敏感操作只接受真实短信验证票据，不能使用固定测试码。
- 绑定与手机号补全有独立限时事务；关联到已有账号前确认，不凭客户端 UID、昵称或头像合并。
- 封禁后的公共说明、无需登录的帮助入口；网络错误与认证失效区分。
- 微博展示仅使用经过服务端验证的身份资料，首次绑定默认不公开，不再伪造昵称或主页链接。
- 保留现有用户资料、收藏与卡册业务；引导完成状态由服务端记录。

### 管理平台

- 独立账号密码登录、独立刷新和退出，移除默认验证码提示。
- 用户管理 → App 用户：服务端筛选/分页、资料/身份/登录/操作记录、安全处置。
- 用户管理 → 登录白名单：关联状态、有效状态、到期时间、责任人和用途；新增不会创建用户。
- 测试验证码配置单独受权：只返回是否配置、开关、版本与操作者，不返回验证码；修改需要原因和版本校验。
- 后台管理员独立管理，账号不变、密码不回显、禁止停用最后一个有效最高管理员。
- 客服入口配置与 HTTPS 域名白名单；无配置时不编造客服账号。

## 本地初始化与验证步骤

管理平台：`http://127.0.0.1:5173`；API：`http://127.0.0.1:8000`。

### 1. 初始化独立管理员（仅首次）

在项目根目录运行，按终端提示输入密码，密码不要写入命令行、聊天、Git 或截图：

```sh
cd apps/api
.venv/bin/python scripts/bootstrap_admin.py --account YOUR_LOCAL_ADMIN --name 本地管理员
```

此脚本只新增独立管理员，不把已有 App 用户升级为管理员，不复制旧凭据。已存在账号应走后台受审计的密码重置流程，不直接覆盖。

账号使用 3–100 位英文字母、数字或 `_.@-`；密码至少 12 位，包含字母和数字。按你的选择，实际本地管理员由你自行在终端创建，本轮未生成密码，也未创建真实管理员或白名单。后台浏览器测试使用单独的临时数据库。

### 2. 配置本地测试登录

1. 使用独立管理员账号登录本地平台。
2. 打开「用户管理 → 登录白名单 → 测试验证码配置」。首次启用必须输入新的 6 位数字字符串（可有前导零），填写原因并确认影响。
3. 新增自己有权使用的测试手机号，设置未来到期时间、责任人、用途并确认授权。
4. 检查记录为“当前有效”；环境能力关闭或已到期时，即使记录为启用也不生效。
5. 在 iOS App 输入该号码，手工输入测试负责人通过受控渠道提供的验证码。2026-10-28 最新界面已移除常驻测试说明，不回显验证码；已登记真实密码的账号也可选择密码登录，测试码不能当作密码。
6. 修改或停用配置后，已发出的旧测试 challenge 应失效。白名单不允许绕过封禁，也不能用于换绑或解绑。

不要再使用 `scripts/set-dev-login-code.py` 或 `DEV_PHONE_CODE` 环境变量；V1.5 不使用通用开发验证码。

### 3. 手工验收清单

- 原手机号重新登录后，用户 ID 和收藏/卡册仍保持原样。
- 添加未注册号码的白名单后，App 用户数量不变。
- 错误验证码连续 5 次后，即使输入正确码也须重新获取。
- 编辑手机号清空旧验证码和 challenge；发送中/登录中不能重复提交。
- 测试码配置版本冲突不覆盖他人修改；读取和操作日志均无明文码。
- App 用户不能登录管理平台；后台令牌不能访问 App 私人数据。
- 封禁、解封、退出、撤销会话分别验证；解封不恢复旧会话。
- 未配置短信或 SDK 时看到明确不可用提示，不显示“发送成功”“绑定成功”。
- App 用户未登录时也能进入帮助页面；没有配置客服联系方式时不出现虚构联系方式。

## 真实渠道启用前的必要工作（本轮未完成外部联调）

### 短信

后端已接腾讯云 `SendSms` 2021-01-11 / TC3 签名接口。配置 `SMS_ENABLED`、`SMS_SECRET_ID`、`SMS_SECRET_KEY`、`SMS_APP_ID`、已审核的 `SMS_TEMPLATE_ID` 和 `SMS_SIGN_NAME`。当前模板请求只有一个参数（验证码），必须与审核模板一致。真实发送会产生服务商费用，本轮自动测试仅模拟 HTTP，不发送短信。

受理不等于送达。网络超时为“处理中”，不可盲目重发。真实短信、限流、运营商送达和换绑流程仍需在受控真机号码上验收。

官方接口参考：[腾讯云发送短信](https://cloud.tencent.com/document/api/382/55981)。

### 微信与微博

服务器实现受控接口：微信授权码由本应用凭据兑换；微博校验 token 的应用归属、UID、有效期，再校验用户资料主体。客户端 UID 不具有认证效力。原始平台 token 不回传业务页面、不保存到审计日志。

**当前 Flutter 安装包尚没有实际接入官方原生 SDK，仅提供失败关闭的 MethodChannel 适配边界。** 因此不仅需要填凭据，还必须补齐 iOS 原生 SDK、注册应用/Bundle ID、URL Scheme/Universal Link、回调和取消逻辑，进行真机联调。这部分不可表述为“已可正常使用”。

1. 在平台登记本 App，完成审核，确认 Bundle ID 与 `com.fanos.app` 匹配。
2. 接入并审计官方 SDK，完成 `com.fanos.app/account_authorization` 的 `isAvailable` 和 `authorize` 原生实现；验证 state、取消、重复回调和前后台切换。
3. 服务端配置微信 AppID/Secret/Universal Link、微博 App Key/Secret/Redirect URI。密钥只放服务端安全配置。
4. 真机确认可信凭据验证、已有账号登录、补手机号、冲突拒绝、绑定、解绑与隐私展示。
5. 通过后才开启 `OAUTH_NATIVE_VERIFIED` 和对应 provider 开关。默认均关闭；仅有服务端凭据不会使当前模拟器获得可用 SDK。

官方 SDK 配置参考：[微博 iOS SDK](https://github.com/sinaweibosdk/weibo_ios_sdk)。

### 协议和客服

正式用户协议、隐私政策、客服域名及联系方式由产品/运营提供，不在本轮捏造。App 的合法 HTTPS 协议地址与服务端 `SUPPORT_ALLOWED_HOSTS` 按实际域名配置；上线前必须验证可达性和内容。客服链接不得携带 token、完整手机号或内部封禁原因。

## 2026-10-28 发布补充：后台重置 App 密码

App 用户管理的列表及详情「更多 → 重置密码」支持设置账号密码。要求用户已绑定手机号、填写操作原因、确认两次密码并勾选下线全部 App 会话。使用记录版本避免并发覆盖；重置保留用户 ID、资产及账号状态，立即撤销该用户现有 App 会话。

独立能力 `auth.users.password` 默认只授予超级管理员，授权时依赖 `auth.users.view`。普通重置继续执行 8–64 位、包含字母和数字且不含空格的规则。接口与审计不返回或保存密码明文，原因字段不得包含新密码。云端初始账号按用户明确指定的一次性初始化单独处理，不写入代码或默认种子。
