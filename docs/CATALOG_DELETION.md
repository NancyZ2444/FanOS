# 图鉴记录永久删除

更新日期：2026-10-10，以用户最新确认的规则为准。

## 状态与关联

| 情况 | 删除条件 |
| --- | --- |
| 从未发布的 Draft | 可以删除；其他业务引用必须先解除，自身未发布的上游归属不阻止删除。 |
| 曾发布后下架，或之后重新保存成 Draft | 所有上下游关联先解除，保存成 Draft 不会清除发布历史。 |
| Archived | 继续严格检查所有上下游关系。 |
| Published / Pending / Rejected | 不能直接删除，先按状态流转处理。 |

发布事实由持久标记、当前状态及既有审计判断；缺少创建 / 发布证明的旧数据按严格规则处理。

检查包含组合、艺人、发行来源、版本、批次、父子活动、成员和公司历史、其他图鉴内容、账号、本命、收藏、心愿单、卡册、翻卡、扫描、反馈、动态、社区、举报、通知及运营配置。已归档的引用仍计入，JSON 对象键和值中的 ID 同样检查。

## 界面操作

七类图鉴列表支持管理员单条及批量永久删除。单条先显示预检结果；有引用时展示类别和数量，无引用时要求不可恢复确认。

下架 / 归档小卡或来源在没有下游引用时，可明确确认解除上游归属，再重新预检。这不会删除收藏等下游关系。组合、艺人的历史经历不通过删除准备入口清空；公司 / 成员历史受保护。批次内小卡可先在批次详情解除批次关系，小卡本体保留。

人工合并的旧卡保留目标关联及旧 ID 跳转，不通过解除归属清除这些历史别名。同时勾选关联两端不能绕过校验；任一项失败整批回滚。

删除清理自身后台元数据和内部图片版本，保留审计、导入历史及事件历史；素材文件不自动删除，避免影响共享图片。

## API 与权限

- 预检：`GET /api/v1/admin/console/deletion-check/{kind}/{id}`。
- 明确解除上游：`POST /api/v1/admin/console/detach/{kind}/{id}`。
- 删除实体：`DELETE /api/v1/admin/console/entities/{kind}/{id}`。
- 删除小卡：`DELETE /api/v1/admin/console/cards/{id}`。
- 批量接口使用 `action: "delete"`，最多 100 条，整批原子处理。

仅管理员可永久删除。状态不符或仍有关联返回 409，关联错误含 blockers 详情。为兼容旧客户端，状态错误代码仍用 `DELETE_REQUIRES_ARCHIVED`，消息已说明允许的状态。权限不足返回 403，不存在返回 404。

数据兼容见 [图鉴更新说明](CATALOG_UPGRADE_20261010.md)。目前使用事务内关联检查；PostgreSQL 并发新增引用、大量 JSON 扫描未专项压测。
