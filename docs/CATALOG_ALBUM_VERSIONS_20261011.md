## 后台功能

- CSV / XLSX 专辑模板新增 `versions` 与 `artist_names`。`name` 只填专辑作品名；多个版本、多个艺人名称均用 `|` 分隔。例如 `name=THIS MAN`、`versions=Standard Ver.|Weverse Albums Ver.`、`artist_names=SEVENTEEN|Jeonghan|Wonwoo`。
- `artist_names` 精确匹配现有组合或个人档案；找不到或不唯一时返回逐行错误，不自动建立或猜测艺人。兼容旧 `group_name` / `idol_name`、JSON `artists`，并接受 `version`、`idol_names`、`idol_ids`。
- 同作品名、同参与艺人集合的不同版本行归入一个父专辑，艺人排列顺序不影响识别。不同艺人集合仍是不同发行。
- 向已有父专辑导入新版本只追加版本，保留原简介、日期、图片、艺人、状态及已有版本 ID。重复版本预检报错；确认前重查冲突，任一失败整批回滚；已完成任务重复确认不重复创建。
- 手动专辑表单支持版本名称，保存后建立独立版本记录，详情版本页可维护编码、图片等。版本记录和兼容名称列表同步；有引用或归并映射的版本不能直接移除。
- 归并后的旧 ID 保留归档记录与原始名称，可从详情跳转父专辑版本页。禁止恢复或解除归并映射后删除，避免历史导入记录失效。版本编辑保留原始数据快照。

## 后续数据升级策略

本次已确认范围已经执行，不再自动扫描名称并拆分。未来补充数据使用新版模板，作品名称和版本分别填入；对旧标题存在歧义的记录，先确定作品、版本和参与艺人，再建立显式映射。已被卡片、活动或其他业务引用的旧发行，需要单独确认引用迁移，脚本会拒绝直接归并。历史卡仍保留发行时归属，不按当前成员身份重写。

脚本 `scripts/normalize_album_versions.py` 默认只读，`--apply` 才执行，并在写入前自动备份。重复执行验证已存映射，不重复新增。整库回退只能在停服、确认应用后没有需保留的新业务写入时使用备份；否则依据映射作定向恢复，避免覆盖后续运营数据。
