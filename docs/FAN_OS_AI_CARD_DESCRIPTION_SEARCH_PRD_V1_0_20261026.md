## 1. 产品结论与目标

用户记得卡面特征，却不知道小卡名称、来源或版本时，可以通过文字描述，在平台已发布图鉴内找到真实小卡。

App 采用“**候选卡网格 + 可调整条件 + 连续补充描述**”。平台增加“**视觉检索标记 + 描述搜索索引**”，支撑检索质量和人工纠正。

对原小卡新增流程的结论：

- 原录入字段、来源规则、贡献者关联和正式审核流程沿用。
- 不增加必须填写的发色、服装、动作等字段，不要求运营填完视觉标记才能发布。
- 正式发布后自动投递搜索处理任务：同步基础字段、建立图片语义索引、生成候选视觉标记。
- 图片语义索引可独立生效；AI 候选标记需人工确认，才进入正式标记检索与具体匹配解释。
- 索引或 AI 标记失败不回滚小卡发布；后台显示失败并重试。尚无语义索引的小卡可参与基础字段检索，但不保证按视觉描述命中。
- 视觉标记属于独立检索附属数据。仅修改它们不应使已发布小卡下架，也不改变原卡的公开资料。

### 1.1 目标用户与场景

| 场景 | 示例 | 成功结果 |
| --- | --- | --- |
| 只记得画面 | 黑发、白色衣服、蓝背景，手在脸旁比耶 | 展示可能匹配的小卡 |
| 知道艺人但不记得版本 | 找某艺人戴帽子的那张自拍卡 | 限定艺人后按画面找卡 |
| 记忆不完整 | 好像是红头发，可能拿着花 | 保留不确定条件，不错误排除目标 |
| 记得背面 | 背面是粉色，有一行英文 | 检索已收录背面并标识命中面 |
| 在某组合页面发现需要查找 | 找这个组合某次活动的蓝衣卡 | 自动带入可移除的对象范围 |

### 1.2 衡量目标

关注用户确认找到目标的比例、前几位候选命中率、平均有效轮数、无结果率、视觉索引覆盖率，以及每次完整找卡会话成本。不能以“模型返回了文字”或“索引成功数量”代替找到目标的效果。

## 2. 当前系统基础与新增差异

| 能力 | 当前本地实现 | 本次要求 |
| --- | --- | --- |
| App 普通搜索 | 在图鉴数据中匹配名称、编号、来源、版本、标签等文字；可搜索多类对象 | 保留原入口，增加专用描述找卡页 |
| 小卡查询接口 | 关键词及组合、艺人、来源、年份、正式标签等筛选 | 增加会话、语义条件、候选排序与查询版本 |
| AI 扫描 | SIFT 特征与 RANSAC 核验，关联原图鉴 Card ID | 保留，另建图文语义检索，不能直接复用扫描向量假定已支持文字 |
| 正式图鉴标签 | 按对象类型管理的扁平标签、标签关联、用户提案与审核 | 可复用词条规范化和审核思路，但视觉标记使用独立范围及绑定 |
| 小卡编辑 | 草稿、驳回、下架状态可编辑；已发布内容须先下架才能走原编辑 | 正式字段沿用；搜索附属标记新增独立维护路径 |
| 图片版本 | 已记录正 / 背面图片版本及来源信息 | 增加语义索引与标记对图片版本、内容指纹的关联 |
| 异步事件 | 已有 Outbox；现有扫描 worker 主要消费正面图片更新事件 | 增加搜索消费者和正背面、发布状态、元数据变化等触发 |
| 后台 AI 索引 | 已有扫描索引状态、失败原因和重试 | 新增“描述搜索索引”，与扫描索引分开查看 |
| 反馈 | 已有缺卡收录、数据纠错与本人进度 | 找卡质量反馈另行记录；图鉴数据问题仍回到原纠错 |

代码核对范围限于当前工作区，未连接生产环境验收。

## 3. 概念、范围与权限

### 3.1 三类“标记”必须分开

| 类型 | 例子 | 数据性质 / 生效方式 |
| --- | --- | --- |
| 正式图鉴字段与标签 | 艺人、组合、来源、版本、既有公开标签 | 现有主数据与审核规则 |
| 视觉检索标记 | 黑发、白色上衣、蓝背景、比耶、背面文字 | 本功能新增的图片附属信息，绑定图片面和版本，经确认用于检索 |
| 处理与索引状态 | 候选待核实、索引构建中、失败、已失效 | 系统运行状态，不是卡面特征，也不作为用户搜索标签 |

AI 候选标记不得直接追加到现有 Card.tags 中。现有正式标签也不能仅按同名就自动认定为某个视觉维度，例如正式标签“蓝色”不能直接推断为“蓝色头发”。

### 3.2 本期边界

纳入：文字输入、对象范围、视觉条件、多轮澄清、正背面检索、结果与历史、后台标记和索引、批量历史数据处理、额度与成本记录。

暂不纳入：语音输入、自由上传照片与文字混合搜索、生成新卡面、全网找卡、自动新增图鉴主体、自动修改拥有 / 心愿 / 卡册关系。已有图片扫描继续从原入口使用。

只返回当前用户有权访问的已发布小卡。搜索命中和用户说“就是这张”均不是图鉴审核或贡献行为。

### 3.3 角色

| 角色 | 能力 |
| --- | --- |
| 游客 | 可看入口和示例；点击开始时登录，登录后恢复输入 |
| 登录用户 | 发起会话、补充条件、看本人历史、反馈匹配质量 |
| 内容运营 content_operator | 查看搜索辅助资料、编辑标记草稿、提交核实、有限批次重试、维护质量样本 |
| 管理员 admin | 确认 / 驳回标记、发布字典变更、暂停检索、批量重建、调整配置和预算 |
| 其他运营角色 | 按现有图鉴权限边界处理，不自动获得图鉴或 AI 管理权限 |

本次新增的视觉标记最终确认权限由管理员控制；内容运营保存草稿不直接改变有效搜索标记。此规则不改变现有正式标签的编辑权限。用户查询原文和后台密钥分别受权限限制，不能向所有运营默认公开。

## 4. App 入口与页面清单

不新增底部导航，不更改原有首页、图鉴、扫描、收藏、我的结构。

| 页面编号 | 页面 / 入口 | 主要内容 |
| --- | --- | --- |

| DS-A03 | 找卡结果页 | 条件摘要、候选网格、追问、继续描述 |
| DS-A04 | 条件编辑面板 | 对象、来源、正背面、视觉条件及确定程度 |
| DS-A05 | 识别对象确认面板 | 同名艺人 / 组合歧义确认 |
| DS-A06 | 本次描述记录 / 历史 | 轮次、条件快照、结果与恢复 |
| DS-A07 | 结果状态与反馈 | 无结果、弱匹配、失败、排除与撤销 |
| 复用页面 | 原小卡详情、AI 扫描、数据反馈 | 保持原有主业务动作 |

入口带入规则：

| 入口 | 默认范围与输入 |
| --- | --- |
| 图鉴首页 | 全部图鉴，空输入 |
| 普通搜索的小卡区域 / 无结果页 | 可带入原搜索文字，但点击开始后才执行 |
| 扫描页“没有图片？试试描述找卡” | 空输入，不自动提交扫描照片或缺卡反馈 |
| 组合 / 艺人详情的小卡列表 | 对应对象范围，以可移除条件显示 |
| 已拥有列表 | 本期不新增专属入口；结果页提供“只看已拥有”筛选 |

跨入口带入的是正式对象 ID，不使用用户个人备注替代全局主体身份。用户可以在本人会话中通过个人备注确定对象，但不得写入公共别名或其他用户的检索词库。

## 5. App 初始页布局与交互

### 5.1 布局

```text
＜ 描述找卡                              找卡记录

说说服装、动作、背景，帮你在图鉴里找
范围：[全部图鉴 ▾]

┌────────────────────────────────────┐
│ 例如：黑发、白衣服、蓝背景，         │
│ 手在脸旁比耶……                      │
└────────────────────────────────────┘
                                          0/500

试试这样描述：
[蓝背景、戴帽子的自拍卡]
[某艺人、黑色西装、拿着花]
[粉色背面，上面有一行英文]

1 次找卡含最多 5 轮分析
剩余会话额度：N
[开始找卡]
```

### 5.2 交互规则

- 输入支持 1～500 个用户可见字符，去除首尾空白后不能全空；不要求至少填写某个视觉字段。
- 示例点击只填入，可编辑；不自动调用模型，不消耗额度。
- 对象范围可选组合或艺人，不要求先填专辑、版本和来源。
- 点击开始前校验登录、功能可用性及额度；服务端再次校验。
- 提交中按钮显示“正在找卡”，禁用重复提交；允许用户返回，处理结果可在会话记录恢复。
- 输入错误、网络失败或登录中断不得清空文字。
- 键盘弹起时输入与提交按钮保持可操作；适配安全区域、大字体和屏幕阅读，不依赖颜色区分条件。
- 本稿默认不边输入边调用 AI。只有明确点击开始或更新结果才执行。

### 6.1 页面布局

```text
＜ 描述找卡                          本次记录

描述：黑发、白衣服、蓝色背景，比耶
[范围：某艺人 ×] [偏好：蓝背景 ×]
[偏好：白衣服 ×]                     编辑条件
[只看已拥有：关]  [正背面：不限]

可能符合的小卡
部分候选动作尚未确认

┌─────────────┐  ┌─────────────┐
│ 完整小卡图  │  │ 完整小卡图  │
│ 艺人名称    │  │ 艺人名称    │
│ 来源 / 版本 │  │ 来源 / 版本 │
│ 匹配线索    │  │ 匹配到背面  │
│ [更多]      │  │ [更多]      │
└─────────────┘  └─────────────┘

可选追问：记得是自拍还是舞台造型吗？
[自拍] [舞台造型] [不确定]

剩余分析：4 轮
[继续补充描述……                     ] [更新结果]
```

顶部是已应用条件，中间是可滚动双列网格，底部是追问与输入区。追问可折叠，不遮住结果。条件较多时显示摘要，点击“编辑条件”完整查看。

每页默认返回 20 个候选，本轮最多展示 100 个推荐候选；这是推荐数量上限，不表述为全库仅有这些记录。分页在本轮排序内继续，不重复调用 AI。

### 6.2 结果卡片

| 元素 | 展示 / 交互 |
| --- | --- |
| 图片 | 完整保留卡边与文字；按命中面展示，背面标识清楚，可切回正面 |
| 身份信息 | 正式艺人 / 组合、来源、版本；沿用现有个人显示名偏好但不改变检索身份 |
| 匹配线索 | 最多展示 2 个已确认且当前有效的视觉标记；没有可核实标记时只写“画面相近，建议核对” |
| 已拥有 / 心愿标识 | 从本人关系读取，只读展示 |
| 点卡面 | 进入现有小卡详情，并保留返回位置 |
| 更多 → 就是这张 | 记录本轮命中，打开详情；不改变拥有和心愿 |
| 更多 → 不是这张 | 从当前会话排除，底部显示“已排除，可撤销” |
| 更多 → 图鉴信息有误 | 打开原卡纠错并带入对象，不作为搜索标签即时修改 |

同一 Card ID 的正背面命中合并为一张结果卡，标注实际命中面；同卡不同来源版本仍按真实 Card ID 区分，不能仅看起来相似就合并。

不展示未经校准的“正确率 98%”。候选不能由 AI 生图补齐，候选 ID 必须被服务端验证为真实可访问记录。

### 6.3 条件编辑面板

| 条件 | 来源与默认行为 |
| --- | --- |
| 组合 / 艺人 | 用户选定或已消歧确认的正式对象，默认必须符合，可移除 |
| 来源 / 版本 / 年份 | 明确指向正式数据时可作为必须符合；模糊表达先保留为偏好 |
| 正面 / 背面 / 不限 | 不限为默认；“背面有字”可解析为背面并显示给用户确认 |
| 只看已拥有 | 本人真实关系筛选，默认关闭，服务端在全体合格数据上应用 |
| 发色、服装、动作、背景等 | 默认视觉偏好；用户明确要求时可设置为“必须符合” |
| 否定条件 | 如“不戴帽子”，明确显示排除意图；不能把未标记当成确认没有 |
| 确定程度 | 必须符合 / 偏好；从“不确定、好像”等表达带入偏好 |

面板分为“已应用”和“待更新”状态。删除或修改条件后点击“更新结果”才生效；放弃编辑恢复原条件，不能让旧结果看起来已经符合新条件。

严格视觉条件只能用当前有效、已确认标记判断。标记未知的卡不能进入“已满足全部严格条件”的结果；用户可主动改成偏好再检索。系统不得为凑结果静默放宽必须条件。

## 7. 连续描述、状态与历史

### 7.1 多轮规则

| 用户表达 / 操作 | 规则 |
| --- | --- |
| “是某艺人的” | 增加或替换主体范围，保留其他兼容条件 |
| “不是白色，是黑色衣服” | 替换服装颜色，不同时累加白 / 黑两个必须条件 |
| “好像拿着花” | 保留为偏好，不强制排除证据不足的候选 |
| “不戴帽子” | 明确否定；未核实有没有帽子属于未知 |
| “不对，重新找” | 引导修改条件或清空重开，不暗自丢失此前约束 |
| 同名主体 | 弹出身份确认面板，用户选定后继续；不猜测 ID |
| 条件互相冲突 | 指出冲突并等待调整，不返回假匹配 |
| “不知道 / 跳过” | 不新增条件，仍可看候选 |
| 回到某一历史轮 | 查看当时条件和结果；继续查询时明确以该轮为基准 |

追问一次最多一个，提供 2～4 个选项及“不确定”。优先问最能区分现有候选的特征，不能反复问已回答的问题。歧义确认和跳过本身不计一次有效分析，后续执行新检索才计算。

首轮需消歧时，原请求进入“等待用户确认”，可尚无有效轮次或查询版本。App 使用原请求 ID 与选定的正式主体 ID 恢复该请求，不重新创建会话、不重复预占或计轮。等待确认默认最多 10 分钟；取消或到期则结束请求并释放预占，保留输入供再次发起。该等待阶段不占用模型执行并发，但同一会话不能再提交另一个分析请求。

### 7.2 结果与异常状态

| 状态 | App 行为 | 额度原则 |
| --- | --- | --- |
| 正常候选 | 展示结果和可选追问 | 有效一轮 |
| 正常零候选 | “暂未找到符合描述的小卡”，提供调整或扫描入口 | 有效一轮 |
| 偏好匹配较弱 | 标“相近结果”，不声称全部符合 | 有效一轮 |
| 搜索系统故障 | 保留输入与上轮结果，说明本轮未更新 | 本轮不扣 |
| 核心语义服务故障，返回基础搜索 | 明示“描述分析暂不可用，以下为普通搜索结果” | 不作为有效 AI 轮 |
| 超时尚未知 | 查询原请求，不重复发起付费分析 | 待确认，不先重复结算 |
| 额度 / 轮数不足 | 可查看已有结果，继续需新会话或额度 | 明确确认后才消耗 |
| 已拥有筛选为空 | 显示“当前条件下没有已拥有的小卡”，允许关闭筛选 | 纯结构化过滤不扣 AI 轮 |
| 结果卡下架 | 移除不可访问项，详情返回明确状态 | 不补扣额度 |

普通零候选不等于现实中不存在。若用户有照片，可进入 AI 扫描；缺卡反馈仍由扫描后的缺失场景发起，不允许仅凭文字描述自动创建图鉴卡。

### 7.3 返回、并发与历史

- 返回结果页保留描述、条件、排除项、候选顺序、轮次和滚动位置。
- 每个会话同一时刻最多执行一个分析请求；重复点击使用相同请求 ID，允许编辑下一轮草稿但不并发刷调用。
- 服务端返回查询版本；迟到响应不能覆盖更新结果。
- 单次执行阶段默认最迟 60 秒由服务端确定终态，可配置；等待用户消歧另按 10 分钟计时。终态截止前 App 查询原请求；截止时若仍未成功提交结果，则原子标记失败、释放预占并解除会话占用。迟到模型结果仅记实际调用成本，不再结算、不提供为本轮成功结果，也不覆盖新请求。
- 历史结果展示前重新校验图鉴可见性、图片与严格条件版本。不能继续把旧图当当前图解释。
- 默认会话可继续 24 小时；找卡记录默认保留最近 30 天，按时间分页，过期会话可看但不能免费继续分析。
- 用户可删除单条或清空记录；原文与可读历史按删除策略清理，必要的匿名费用统计和安全审计单独保留，不继续作为本人可恢复会话。
- 历史不对其他用户公开。换账号后清理前账号的页面缓存与待提交内容。

## 8. 检索流程与数据分层

### 8.1 每次查询

输入与会话 → 确认对象 / 条件 → 先筛当前可访问且符合正式限制的数据 → 多路召回 → 排序去重 → 再次校验状态与严格条件 → 读取正式字段渲染结果 → 返回可选追问。

建议三路召回：

1. 名称、编号、别名、正式来源与标签关键词。
2. 人工确认的视觉标记、经确认的视觉描述及画面文字。
3. 正背面图片的跨模态语义向量。

同一画面的多个视觉条件，默认须在同一有效图片面满足；属于同一人的特征还须属于同一主体。仅当用户明确描述“正面黑发、背面蓝背景”时，允许分面验证后按 Card ID 合并。严格条件不能跨正背面、跨人物凑齐，条件面板应显示各条件所属图片面。

模型只负责理解和辅助排序，正式身份、发行信息、图片、关系及权限由业务数据决定。视觉候选量不足时可以减少结果，不制造卡片或编造匹配原因。

### 8.2 AI 候选标记与图片向量的不同用途

| 数据 | 自动生成后是否参与搜索 | 是否直接对 App 展示 |
| --- | --- | --- |
| 图片语义向量 | 完成检查并绑定当前图片后，可用于相似召回 | 否，只体现为候选排序 |
| AI 候选视觉标签 / 描述 / OCR | 默认不进入正式标签检索，待后台确认 | 否 |
| 已确认视觉标记 | 可用于召回、严格条件判断和匹配解释 | 仅按需展示少量有效线索 |
| 正式主数据与原有标签 | 按原规则参与 | 按已有图鉴规则 |

因此“标记尚未核实”不等于“小卡不能被描述搜到”。图片索引就绪即可提供语义候选；需要可靠标记的具体解释和严格过滤，按已确认信息执行。

后台模型重新生成候选时，不自动覆盖人工确认的标记；应显示新旧差异，交由审核人员选择。

### 8.3 排序与版本

先满足必须条件，再按视觉偏好、已确认标签和图片相似程度排序。相同得分使用稳定顺序，分页不因刷新产生随机重复。

本轮缓存保存候选和索引版本，点击、翻页时仍校验当前权限和数据。若原图、严格条件或索引版本变化影响排序，可提示“资料已更新，更新结果”；单纯服务端纠正版本而重放原查询，不重复收取会话额度，也不消耗分析轮数。会话过期或轮数耗尽后，仍可按原条件刷新可见结果；此操作不能携带新描述或借机重新进行语义理解。用户主动改描述仍按新轮次或新会话计算。

全局缓存不得包含某用户的已拥有、心愿或私有备注；个人过滤和展示在用户权限范围内执行。


## 9. 后台视觉检索标记：字段与数据规则

### 9.1 原卡正式信息只读引用

组合、艺人、来源对象、来源版本、发行日期、卡片类型、原有正式标签从主数据读取。标记工作台显示这些信息，但修改时跳转原图鉴编辑 / 纠错流程，不允许模型看图推断后直接覆盖。

### 9.2 视觉维度

下列是第一版字典范围。视觉特征允许未知，不要求每张图填满；图片面及版本是必需的关联上下文。

| 维度 | 建议字段键 | 类型 / 例子 | 规则 |
| --- | --- | --- | --- |
| 图片面 | image_side | 正面 / 背面 | 必须绑定实际存在的对应图片 |
| 人物数量 | person_count | 0、1、2、多人、未知 | 不推断照片人物身份 |
| 画面主体 | subject_ref | 全图、主体 1、主体 2 等 | 多人特征可按主体分组；无可靠主体分组时不得声称同一人同时满足所有条件 |
| 发色 | hair_color | 黑、棕、金、红、粉、多色等 | 可多选；光线导致不确定时保留未知 |
| 发型 | hairstyle | 短发、长发、刘海、马尾等 | 外观描述，不用于猜测性别或身份 |
| 上装颜色 | upper_clothing_color | 白、黑、蓝、多色等 | 与背景色分开 |
| 下装颜色 | lower_clothing_color | 与上装同类颜色 | 未入镜为不适用 / 未知，不强填 |
| 服装类型 | clothing_type | 衬衫、西装、针织、外套等 | 可多选，不把主观风格当确定事实 |
| 动作 / 手势 | gesture | 比耶、比心、托腮、举手等 | 人物与动作关系明确，不跨人物拼接 |
| 表情 | expression | 微笑、闭眼、眨眼等 | 只描述可见表现，不推断内心情绪 |
| 配饰 | accessory | 帽子、眼镜、耳饰、发饰等 | 支持存在 / 明确不存在 / 未知 |
| 手持物 | held_object | 花、话筒、玩偶等 | 与背景物体区分 |
| 背景主色 | background_color | 蓝、白、粉、渐变、多色等 | 不与服装或卡边颜色混用 |
| 背景 / 构图 | background_type、framing | 纯色、室内、户外、近景、半身、全身等 | 仅记录可辨认内容 |
| 卡边 / 图案 | border_color、graphic_pattern | 白边、星星、花纹等 | 不识别品牌真伪，不自动推定发行版本 |
| 画面文字 | visible_text | 经核实的 OCR 文字，可空 | 保留文字原样，不当作正式卡名、艺人或来源证据 |
| 辅助描述 | visual_summary | 最多 500 个用户可见字符的中性描述 | 人工确认后可用于检索；不添加图片看不到的发行事实 |

颜色、动作等词条使用受控字典，支持多语别名和同义词，如“V 手势 / 比耶”。同一个词在不同维度有独立含义；“黑色上衣”和“黑色背景”不能共用一个不区分维度的绑定。

### 9.3 每条标记需要保存的内容

| 信息 | 目的 |
| --- | --- |
| Card ID、正 / 背面、图片版本、内容指纹 | 确保标记对应正确图片 |
| 维度、标准词条 ID、原识别文本、主体范围 | 支持检索与纠正，不仅保存一个自由字符串 |
| 观察状态 | 有此特征 / 明确没有 / 未知 / 不适用 |
| 来源 | AI 候选、运营补充、审核修正、既有资料映射 |
| 模型与提示模板版本 | 追踪机器建议的来源；人工内容可为空 |
| 当前审核状态、提交人 / 时间、确认人 / 时间 | 确定哪些值可用 |
| 原值、建议值、最终值、修改原因 | 支持追溯和冲突检查 |
| 人工保护标记 | 模型重跑不得覆盖已核实内容 |
| 原始质量分数（如供应商提供） | 仅供后台参考，不转为 App 正确率或自动审核结论 |

“未标记帽子”不能等于“不戴帽子”。只有适用图片中经确认的明确不存在，才满足严格否定条件。

### 9.4 旧正式标签如何使用

现有正式标签继续正常参与原有关键词搜索。需要映射到视觉维度时，管理员必须明确配置映射并核实其适用对象；不能全量自动按名称猜测。

现有标签框架没有完整的逐图片版本、主体、否定和未知机制，因此本版逻辑上新增独立视觉标记及字典范围。是否复用底层表由技术设计决定，接口与后台必须防止混写。

用户说“就是这张 / 不是这张”只产生检索质量反馈；不能自动创建正式标签、确认视觉标记或修改全局排名规则。

### 10.1 菜单结构

1. 视觉检索标记。

模型连接、预算和用户额度由统一 AI 配置承接，但本期仅启用找卡相关能力。已有“AI Scan 索引”保留原用途。

### 10.2 视觉标记列表

筛选：Card ID / 名称、组合、艺人、来源、原卡状态、正背面、候选 / 待审核 / 已确认 / 已失效、是否有人工修正、更新时间、处理人。

列表列：

## 11. 标记、索引与覆盖状态

### 11.1 标记审核状态

| 状态 | 含义 | 是否参与正式标记检索 |
| --- | --- | --- |
| 无标记 | 尚无候选或人工内容 | 否 |
| AI 候选 / 编辑草稿 | 机器建议或人工未提交内容 | 否 |
| 待审核 | 已提交核实 | 否；同图旧生效版可继续使用 |
| 已确认 | 管理员确认且对应当前有效图片 | 是 |
| 不采纳 / 已撤销 | 被拒绝或确认不再使用 | 否 |
| 已失效 | 图片已变、适用范围变化或版本不匹配 | 否，不可继续以旧值解释新图 |

模型任务状态另记为待执行、执行中、成功、失败、已过期；任务成功不自动把标记变为“已确认”。

换图后旧标记保留历史，但不沿用到新图。人工可以对照新图重新确认，系统不能只复制旧标签并标记为有效。

### 11.2 图片语义索引状态

| 状态 | 行为 |
| --- | --- |
| 待构建 / 构建中 | 可用基础字段查询，不承诺当前面的视觉命中 |
| 就绪 | 对应当前图片内容和指定模型，可进行语义召回 |
| 更新中 | 同图兼容的旧版可继续用；旧图片索引不能继续用于当前图 |
| 失败 | 记录阶段与原因，允许重试，原卡主状态不变 |
| 已失效 | 版本或图片不符，禁止作为有效语义结果 |
| 已暂停 / 排除 | 原卡不可检索，或管理员暂停该卡的语义处理 |

后台分别显示“主数据可检索”“正面索引”“背面索引”“标记审核”四项，不能用一个绿色“已完成”代表全部流程。

管理员暂停语义处理时，基础字段仍可按原卡可见性检索；若要从本功能整体排除该卡，须单独设置并记录原因。该设置不等于从普通图鉴下架。

### 11.3 版本与并发

至少校验：主卡检索修订号、图片面与内容指纹、标记生效版本、字典版本、向量模型版本。相同 URL 被替换为不同图片也必须识别变化，不能仅比较 URL。

保存草稿和审核前再次检查图片及标记基准；有人先确认了新版本时提示冲突。模型迟到候选不能覆盖人工确认内容，过期任务只能记日志，不重新激活旧图索引。

正式标记更新、审计记录和索引更新事件在同一事务提交。后台显示“已确认，检索更新中”；撤销或失效的标记立即停止用于过滤和解释，不能等旧缓存自然过期。

## 12. 对原小卡新增流程的影响

### 12.1 后台手工新增的完整流程

1. 运营按原表单填写组合、艺人、来源、版本等资料，上传正面及需要的背面。
2. 保存为原小卡草稿，获得真实 Card ID。视觉标签不是保存或提交审核的必填项。
3. 新增可折叠区“描述找卡辅助信息”：显示图片和处理状态；运营可选“生成候选标记”预处理。
4. 未正式发布的草稿，即使预生成索引或已有人工标记，也不能被 App 描述搜索召回。
5. 按原图鉴规则提交审核、发布。发布事务成功时同步投递检索更新事件。
6. 发布后基础数据按当前主数据可见；图片索引独立异步构建，AI 候选标记进入后台待核实。
7. 已在草稿阶段完成且图片、模型和版本一致的处理可复用，不重复付费执行。
8. 管理员确认标记后更新辅助检索信息；小卡本身不需要再次下架发布。

新增区建议提示：“发布后将自动建立描述搜索索引。视觉标记可稍后核实，不影响图鉴发布。”

### 12.2 原有必填与审核规则

- 原组合 / 艺人 / 团卡关系、来源、图片、双面规则及正式发布校验继续由现有逻辑控制，不在本功能重新定义。
- 用户提交图片维持原来源类型与提交者关联，不因生成搜索标记改成“平台原创”。
- 原允许用户提交图不提供来源链接的规则继续保留，本功能不额外补设强制 URL。
- 自动分析不代表图鉴审核通过，也不改变图片是否允许使用的既有判断。
- AI 供应商故障、候选待核实、索引构建失败不能作为强制阻塞原卡发布的原因。
- 原卡发布成功与描述搜索全部就绪是两个结果，后台分别提示。

### 12.3 AI 扫描缺卡一键转图鉴

扫描缺卡反馈 → 后台采用图片并转原小卡草稿 → 沿用原字段确认与发布 → 已收录及贡献关联按原流程生效 → 异步加入描述搜索处理。

搜索处理失败不撤销“已收录”，也不抹去提交用户、图片版本和贡献来源。未采用的反馈图片不能被当成正式图鉴输入公开检索。

### 12.4 批量导入与批次生成

现有批量导入 / 生成先产生草稿，正式发布后才进入公开描述搜索。沿用原批次校验和事务规则，不因本功能变成导入即公开。

对大批量发布，在提交后拆分受预算控制的后台任务，列表显示总数、成功、待处理、失败及逐项原因；不在发布请求内同步调用模型。只重试失败且仍是当前版本的项，不重做已成功项。

## 13. 小卡变更触发矩阵

| 事件 | 标记处理 | 索引与 App 影响 |
| --- | --- | --- |
| 新增 / 导入草稿 | 默认不自动付费处理，可手动预分析 | 不公开召回 |
| 首次发布 / 重新发布 | 校验当前图与候选 / 生效标记是否一致 | 同步基础文档，补建缺失语义索引 |
| 同图修改艺人、组合、来源、版本、正式标签 | 保留仍适用的视觉标记 | 更新事实字段及搜索文字，不为纯文字改动重跑视觉模型 |
| 换正面图 | 正面旧标记失效，背面未变可保留 | 重建正面；不得用旧正面向量解释新图 |
| 换背面图 | 背面旧标记失效，正面未变可保留 | 必须有独立背面触发，不能依赖现正面扫描事件 |
| 删除背面 / 改为无背面 | 背面标记退出有效集合 | 移除背面检索项，不继续显示“匹配到背面” |
| 仅改图片来源说明，内容相同 | 核对新版本与相同内容的适用性 | 可复用计算结果并更新版本关联，不重复视觉调用 |
| 用户纠错采用后发布 | 按最终采用字段决定图像或事实更新 | 以提交后的最终版本处理，拒绝中间事件回退 |
| 仅改视觉检索标记 | 独立草稿 / 核实，不修改主卡 | 更新标记检索，原卡保持当前发布状态 |
| 下架 / 归档 | 内部保留标记历史 | 立即在返回层排除；异步停用索引 |
| 恢复归档 | 原流程恢复为草稿，标记供复核 | 重新发布前不能召回 |
| 删除卡 | 保留必要审计，清理检索关联 | 删除对应文档；迟到任务不得复活 |
| 合并 A 到 B | 不把 A 的视觉标签直接覆盖 B，核对 B 自身图像 | 停用 A，更新 B；最终只显示有效主卡一次 |
| 关联艺人 / 组合 / 来源改名或别名变化 | 正式身份从源对象同步 | 按依赖关系刷新受影响卡，不只看 Card.updated_at |
| 关联主体不可公开 | 按图鉴现有可见性规则处理 | 不通过搜索摘要泄漏被隐藏主体资料 |
| 标记字典停用 / 合并 | 失效或迁移对应绑定 | 刷新条件、解释及文本索引，旧词历史可追溯 |
| 模型升级 | AI 候选对比更新，不覆盖人工结论 | 建立新模型索引，验证后切换，不混用向量空间 |

### 13.1 当前代码需要补的触发点

当前保存已发布小卡并非自动下架，而是拒绝直接编辑；普通主资料编辑要先按原规则下架。搜索标记独立维护路径是本次新增能力。

小卡纠错可能在同一事务里依次执行下架、保存、提交、发布。消费者按最终提交状态和单调版本处理；旧“下架”事件晚到时不能删除新发布索引。

现有扫描 worker 主要消费正面图片更新事件。发布、背面更新、主数据变化需要新增描述搜索消费者；不能仅接上扫描 worker 就宣称这些能力完成。

合并和删除当前没有完整的描述索引事件，需要补齐。媒体转存、裁切后换图也应按实际内容版本更新，避免后台看见新图、搜索仍用旧图。

描述搜索仅召回当前已发布且符合公开范围的小卡。某用户在已拥有 / 历史记录里可以查看下架卡，不等于该卡可以继续通过本功能被检索；也不能照搬现有扫描代码的候选状态范围。

### 13.2 幂等与乱序保护

任务标识至少包括 Card ID、图片面、目标修订号、内容指纹和模型 / 模板版本。写入前重新检查源数据，过期任务结束为“已过期”，不得覆盖新结果。

同一原图的重复事件可复用已有有效计算结果；重建任务和模型实际尝试分别记录，防止重复收费。副作用通过事务事件可靠投递，主数据提交失败不得创建公开搜索结果。

## 14. 后台索引、质量与统一 AI 配置

### 14.1 描述搜索索引页

```text

已发布卡 N ｜ 正面覆盖率 ｜ 背面覆盖率 ｜ 失败任务 ｜ 今日调用费用

卡 A    正面 v3     模型 M1 / v3   模型 M2     更新中  ...         详情
卡 B    背面 v2     无             模型 M1     失败    ...         重试
```

单项详情展示源图片、主卡公开状态、内容指纹、当前与目标版本、各处理阶段、实际尝试次数、最后错误、预计 / 实际费用和任务日志。错误使用“图片读取失败、模型限流、结果格式异常、索引写入失败、版本已过期”等可处理原因，不只显示“失败”。

操作规则：

- 重试失败：只重试失败且仍需处理的阶段；图片向量成功而标记生成失败时，不重复算向量。
- 重建：选择模型版本、图片面和对象范围，预览卡数、图片数及费用估算；管理员确认后执行。
- 暂停批次：停止派发新任务；已被供应商接受的任务可能完成并产生费用，后台清楚显示。
- 取消批次：未派发任务取消，已运行结果按源版本校验处理；取消不删除原有有效索引。
- 暂停单卡语义检索 / 本功能整体排除：分别操作，并展示差异及原因。
- 恢复：重新核验公开状态和图片版本，不能直接恢复过期索引。

人工维护的有效标记独立保存；删除或重建向量索引不得连带删除人工标记与审计。

## 15. 历史小卡补建与日常运维

现有小卡不会因为新功能上线自动拥有完整视觉资料，需要一次历史补建。

1. 盘点当前已发布小卡及有效正背面图片，识别缺图、重复内容、无效链接和已有标记。
2. 先选有代表性的组合、艺人、单人 / 多人、正背面样本，完成建库和人工效果核对。
3. 按批次生成图片向量和候选标记，优先保障在线查询资源；人工确认按使用频率和问题样本推进，不要求全量逐卡确认才能试点。
4. 批次运行期间发生换图、下架或删除，以当前版本为准；不把盘点时的旧快照重新上架。
5. 记录未覆盖原因、成功数、失败数、过期数和费用，支持断点续跑。
6. 覆盖率和效果通过试点评审后扩大范围；模型或字典升级继续采用可回滚批次。

覆盖率分开计算：正面语义覆盖率 = 就绪且版本有效的正面数 / 公开范围内有效正面数；背面覆盖率采用实际存在有效背面的数量为分母；人工标记覆盖率另列。无背面的单面卡不能算背面失败。

低覆盖区域可在 App 范围提示“部分小卡正在完善检索资料”。尚无索引不代表未收录，后台不应要求运营重复新增同一卡。

## 16. 用户额度、平台费用与重复请求

本版建议按“找卡会话”而不是每条消息扣用户次数；具体免费 / 会员月额度由既有会员方案另行确定。

| 动作 | 会话额度 | 分析轮数 |
| --- | --- | --- |
| 打开页面、填示例、编辑草稿 | 不扣 | 不扣 |
| 新会话首次完成有效分析，含正常零结果 | 扣 1 次 | 消耗第 1 轮 |
| 同会话补充自然语言并成功执行 | 不再扣会话 | 每次消耗 1 轮 |
| 同名主体确认、追问跳过 | 不单独扣 | 不单独扣；真正执行后计对应分析轮 |
| 点击追问答案并更新结果 | 不再扣会话 | 需要新语义分析时消耗 1 轮 |
| 仅调整已解析的对象 / 正背面 / 拥有 / 严格程度等结构化条件 | 不扣 | 不扣；重新查询整个合格集合，不能只过滤当前 20 张 |
| 翻页、打开详情、排除 / 撤销候选、查看历史 | 不扣 | 不扣 |
| 图鉴 / 索引变化导致原条件刷新 | 不扣 | 不扣；保留原已解析条件，不借机接受新描述 |
| 系统失败或仅普通搜索降级 | 不结算新会话 | 不扣失败轮 |
| 24 小时到期或 5 轮用尽后继续 AI 分析 | 明确提示并由用户确认新会话 | 从新会话第 1 轮开始 |

结构化重查仍受请求频率和平台资源限制，但不隐藏调用昂贵的 AI 再向用户扣轮。字段编辑器如果必须重新理解自由文本，按钮前需说明将使用一轮分析。

服务端先预占额度，只有产生可供恢复的有效分析结果后结算；失败释放预占。相同请求 ID、重复点击和网络重试只能结算一次。客户端超时但服务端已在最终截止前成功时，恢复原结果及原扣费记录；超过最终截止才到达的结果按第 7.3 节丢弃，不再结算。不能既退额度又无限复用成功结果。

正常零候选属于完成检索；系统故障导致的假零结果必须归为失败。会话删除不返还已正常使用的额度。新会话确认前显示预计使用 1 次，不能通过自动跳转静默购买或扣费。

平台实际费用与用户额度独立：失败的供应商请求也可能产生费用，应如实记录。单会话成本包括理解、文本向量、追问 / 重排和实际重试；建库成本包括图片向量、候选识别及索引存储。**不把上一版每月 2,000 元云预算视为已含这些新增模型费用。**

预算达到上限时优先暂停历史补建；在线预算不足则关闭新分析并保留已有结果与普通搜索，明确说明未扣次数。具体单价由接入模型和真实账单替换，本稿不虚构固定成本。

结果至少包含：真实卡 ID、当前正式展示字段、当前图片与匹配面、当前有效的匹配线索、本人关系标识、可访问状态、查询版本及分页游标。匹配线索引用已确认标记版本，不能只接受模型生成的一段理由。

### 17.3 后台接口能力

分开提供视觉标记草稿、提交、确认 / 驳回 / 撤销，词典草稿与发布，索引状态与任务创建 / 重试，检索排除设置，质量样本及配置管理。每个写操作校验角色、源版本和幂等键，记录审计。

审核接口须带基准图片与标记版本；版本冲突返回可核对的差异，不自动覆盖。后台标记写接口不接收主卡状态、艺人 / 组合、来源或贡献者的修改。

## 18. 性能、可用性与数据保护

- 初期建议目标：在约定试点数据量和并发下，首轮完整结果 P95 不超过 8 秒，纯结构化筛选 P95 不超过 2 秒；作为压测和评审目标，不作为当前已达成指标。超过 2 秒展示处理反馈，达到配置超时后按原请求查询和降级规则处理。
- 主卡发布、下架、换图在结果展示前进行最新状态校验；任何检索延迟不得让不可公开卡重新可见。新索引尚未完成可以降低召回覆盖，不能使用旧图伪装新图。
- 输入和 OCR 都按数据处理。其中出现要求修改图鉴、暴露密钥或忽略规则的文本，不成为模型可执行指令；检索模型没有主数据写权限。
- 对描述长度、请求频率、会话并发、候选数量和模型输出大小设服务端限制。异常频率返回重试提示，不无限并发重试供应商。
- 日志不记录密钥；用户原文只在受控存储保留。当前建议可读历史保留 30 天，业务删除与备份清理周期在上线技术方案中落实；审计数据按必要范围最小化，不把原文无限留在模型调用日志中。
- 模型供应商仅接收完成当前能力必要的文本 / 图片和匿名请求标识，不传用户手机号、账号凭证或完整拥有清单。使用现有公开图鉴图片，不因本功能自动开放用户私有上传。
- 监控区分服务故障、真实零结果和覆盖不足；模型不可用时可关闭新增入口和分析，普通搜索与原小卡录入仍正常工作。

## 19. 验收标准

| 编号 | 场景 | 必须达到的结果 |
| --- | --- | --- |
| DS-01 | 从图鉴、普通搜索、扫描、艺人 / 组合进入 | 入口和带入范围正确；不自动发起计费分析 |
| DS-02 | 游客输入后登录 / 网络失败 | 恢复原文字与范围，不清空 |
| DS-03 | 点击示例、空白、超长文本 | 示例只填充；空白和超长阻止提交 |
| DS-04 | 首轮正常结果 | 双列真实卡片、条件、继续描述、轮数可见；可进入原详情并恢复位置 |
| DS-05 | 连续补充与纠正颜色 | 正确增加 / 替换条件，旧结果与待更新条件区分 |
| DS-06 | 首轮同名艺人、条件冲突 | 明确确认或修改；用原请求恢复，无有效轮次也可消歧，不重复预占 |
| DS-07 | 必须条件与偏好 | 必须条件不满足不返回；偏好可展示相近候选并明确说明 |
| DS-08 | 严格“不戴帽子” | 未知不能等于明确没有；只有有效确认信息满足 |
| DS-09 | 多人、正背面多条件 | 不跨人物或跨面拼接；明确分面描述才允许各面验证 |
| DS-10 | 正背面同时命中同一卡 | 合并 Card ID，正确展示命中面，可看正面 |
| DS-11 | 已拥有筛选和分页 | 对完整合格集合筛选、稳定分页；不只筛当前页，不重复扣轮 |
| DS-12 | 就是 / 不是 / 撤销 | 正确记录质量与排除；不改拥有、贡献或正式标签 |
| DS-13 | 零结果和系统失败 | 文案和计费不同；不能把错误当零结果；不从文字直接提交缺卡 |
| DS-14 | 重复点击、断网、超时后成功 | 一次请求只结算一次；截止前成功可恢复，最终超时释放占用，迟到结果不再扣次或覆盖 |
| DS-15 | 五轮用尽、会话到期、删除历史 | 新描述需明确新会话；系统原条件刷新不扣轮，旧结果按权限可看，删除记录不能跨账号恢复 |
| DS-16 | AI 候选生成成功但未确认 | 后台候选可见；不写 Card.tags、不用于严格过滤或具体解释 |
| DS-17 | 向量就绪但标记待确认 | 可以语义召回，不能展示未核实的具体标签理由 |
| DS-18 | 人工确认 / 部分采纳 / 撤销 | 有审计与版本；有效集合正确；撤销立即停止严格判断和解释 |
| DS-19 | AI 重跑、两人并发审核、换图后审核旧稿 | 不覆盖人工结论，冲突可见，旧图审核不生效 |
| DS-20 | 标记词典改名、别名、停用、合并 | 维度区分、映射清楚；受影响条件和索引更新，不混入正式标签 |
| DS-21 | 内容运营与其他角色尝试确认 | 服务端按权限阻止；按钮隐藏不是唯一控制 |
| DS-22 | 新增小卡不填视觉标记 | 可按原字段校验保存、送审、发布；AI 不成为主卡必填门槛 |
| DS-23 | 已发布小卡只修改视觉标记 | 不下架、不改主卡状态、不改变贡献和已有关系 |
| DS-24 | 缺卡转图鉴、用户提交图片 | 来源链接豁免和提交者关联保留；发布即沿用原收录规则，索引失败不撤回收录 |
| DS-25 | 批量导入、批量生成、批量发布 | 草稿不被搜索；发布后正确投递任务，同版本不重复计算 |
| DS-26 | 主卡改正式字段后重发 | 按原下架 / 编辑 / 审核流程；正式信息及时更新，同图无需重复视觉识别 |
| DS-27 | 正面换图、背面换图、删除背面 | 各面独立失效 / 构建；不保留旧图片理由或已删背面结果 |
| DS-28 | 同 URL 改图片、转存或裁切 | 按内容与版本判断，旧结果不能覆盖新图 |
| DS-29 | 下架、归档、恢复为草稿 | 当前结果和历史移除不可检索项；重新发布前不召回 |
| DS-30 | 删除、合并和旧任务晚到 | 删除卡不复活；合并后只展示有效主卡，不把原卡标记盲目覆盖目标 |
| DS-31 | 纠错同事务下架至发布、乱序消息 | 以最终版本为准，旧下架事件不删除新发布结果 |
| DS-32 | 关联艺人 / 组合 / 来源变更 | 更新依赖卡正式检索字段，不依赖每张 Card.updated_at 自行变化 |
| DS-33 | 标记确认后索引写入失败 | 主卡不受影响；后台显示需更新和可重试，不重复执行已成功昂贵阶段 |
| DS-34 | 索引暂停与全功能排除 | 两种操作作用范围一致；不误改普通图鉴发布状态 |
| DS-35 | 模型换版、批量补建暂停与恢复 | 新旧版本隔离、断点可续、预算可控；回滚不抹除人工标记 |
| DS-36 | 越权、账号切换、恶意输入 | 他人记录不可读，私人缓存隔离，输入不能改系统指令或主资料 |

上线效果另用固定评测集验收，覆盖口语、省略、模糊记忆、否定、多人物、近似版本、正背面和真实无目标的描述。统计 Top 5 / Top 20 命中率、误满足严格条件比例、无目标误引导率、P95 耗时和每会话成本；命中目标由人工确定，不用模型自评作为标准。门槛在试点前与产品确认，并记录评测集和版本。

## 20. 交付顺序、评审项与依据

### 20.1 建议交付顺序

| 阶段 | 交付内容 | 退出条件 |
