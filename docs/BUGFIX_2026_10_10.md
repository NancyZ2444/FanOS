# Fan OS · 2026-10-10 修复与验证

本轮更新 Flutter App、FastAPI、数据库迁移和 OpenAPI；没有重新打包或覆盖 iOS 测试包。

## 九项问题

1. **后台图片未展示**：公开图鉴补充组合、艺人默认 `image_url`；Flutter 保留并使用组合、艺人、专辑、活动、周边及小卡正反面图片。共享图片组件处理网络 / 本地图片，加载失败才使用占位。首页推荐、图鉴列表 / 搜索 / 详情、本命头像、收藏、翻卡、动态发布者同步使用对应默认图。图鉴和首页下拉刷新可读取后台最新已发布数据。
2. **分类占比**：六类入口合并成一排，每项高度 76，保留点击入口，不再使用两排大卡片。
3. **组合详情**：成员卡固定高度 82，长名称省略，减少大块留白；大图和头像优先采用后台组合 / 艺人默认图。专辑、活动、周边详情也使用后台对应图片。
4. **本命数量**：新状态不再隐式选中四位示例艺人。选择页使用独立草稿，只统计当前图鉴内有效选择；“完成”等待 API 成功后保存，取消 / 返回不改原选择。已归档的旧 ID 不计数、不随新选择提交。API 拒绝未在选择列表中的主本命，防止自动追加额外艺人。
5. **主页背景**：编辑资料支持相册选择、预览、保存、移除；后台持久化，重新登录恢复，公开主页也可展示。头像同样通过真正上传接口保存，不再仅保存本机路径。
6. **其他人主页返回**：正常、加载中、用户不存在的主页均提供返回按钮。真实 API 模式从用户接口读取资料，不再只查示例用户；公开相册 / 卡册采用服务端可见数据。
7. **多卡识别**：修正最大外框抑制内部小卡的问题。排除包含多张独立卡片的相册 / 背景外框，再逐张透视裁剪、匹配官方索引；各张拥有独立候选和状态。测试覆盖外框中的六张小卡、重复卡及部分未识别，不自动写入收藏。
8. **反馈成员筛选**：选择组合后仅展示该组合成员（含过往成员）；切换 / 清空组合清除旧艺人选择。后台也校验组合与成员关系。
9. **反馈历史和进度**：增加“我的扫描反馈”，可从个人主页或 AI Scan 顶部进入；提交后进入历史。支持下拉刷新、分页、展开详情，展示待处理 / 处理中 / 已完成 / 未采纳 / 暂未收录、更新时间、备注、处理说明及关联图鉴卡片。后台处理原因也返回用户；只允许查看本人记录。

## 数据和部署影响

- 新增 `users.background_url`，迁移 `b610_profile_background`。本机数据库已升级至该 head，同时应用此前待执行的 `f310_catalog_operations`；不重置、不重新 Seed，不修改已上传素材或本命记录。
- 升级前 SQLite 备份：`output/backups/fan_os_before_20261010_profile_background.db`。头像 / 背景替换和移除不会删除旧媒体文件。
- 新接口：`POST/DELETE /api/v1/me/profile/images/{kind}`（`avatar` / `background`）；`GET /api/v1/scan/feedback`（offset / limit）；`GET /api/v1/scan/feedback/{feedback_id}`。
- 上传主页图片只接受可解码图片，最大 10 MB / 2400 万像素，转换为 JPEG；后台默认图仍须已发布，草稿 / 下架数据不通过此修复公开。
- API 与 Flutter 需配套使用。真机连接时，`API_BASE_URL` 和 `PUBLIC_MEDIA_BASE_URL` 都必须是手机可访问的地址，不能沿用本机 localhost。
- 多卡识别优先保证独立、完整可见的卡片；重叠、遮挡、严重反光和未知图片仍可能未识别。上传更多官方小卡正面并完成索引才能匹配相应卡片，组合 / 艺人头像不会成为小卡识别参考图。
