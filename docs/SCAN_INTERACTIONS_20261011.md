# 扫描结果批量处理和反馈来源更新

2026-10-11。本次将扫描结果改为紧凑的多卡列表，支持独立的批量收藏／喜欢和拥有标记；主动反馈可选择当前官方来源与专辑版本，或提交图鉴缺失内容。扫描列表、选择状态和滚动位置在查看详情、返回反馈表单后保留。

## 多卡处理

- 左侧实际裁剪图，右侧官方候选、来源、相似度和现有拥有数量；移除原来大幅并排对比图和重复候选缩略图。其他候选以小缩略图展示，可点图查看详情、点选择按钮确认。
- 「全选推荐」经用户确认后选择高置信度推荐及已确认对象，不替用户确认低置信度或未知结果，也不会直接写入收藏。
- 「清空选择」只取消本次批量勾选，不删除扫描历史、候选、反馈、喜欢或拥有。
- 「收藏/喜欢」对应 Wishlist，以官方 Card ID 去重，不增加 Owned；「标记拥有」按独立 Detected Card ID，每个实物实例数量 +1。同版重复实物可累计多张，但喜欢只保存一条。
- 成功标记拥有后仍可对这些对象添加喜欢；同一扫描对象不会再次增加拥有数量。未确认的卡必须先选择正确图鉴。
- 请求期间禁止重复提交，失败保留勾选和候选，只有成功后才更新本地数量／喜欢；重试由服务端防重复。
- 进入小卡详情不关闭扫描页。返回保留列表、勾选、确认状态、保存结果与滚动位置；详情加载中、失败或已下架也提供返回按钮。
- AI 候选弹窗和手动图鉴搜索均支持查看详情再返回。候选里没有正确卡时，可从「搜索更多图鉴」进入完整搜索。
- 结果页面按 Scan Session ID 区分状态，避免同一路由更换扫描会话时沿用旧对象的选择。

## 主动反馈

选择来源后，通过服务端获取官方已公开条目，而不是让用户只填自由文本：

| 来源 | 可选择的官方资料 |
| --- | --- |
| 专辑 | 官方专辑、对应版本 |
| 签售 | 签售／视频通话类活动 |
| 演唱会 | 演唱会／巡演类活动 |
| 活动 | 官方活动 |
| 周边 | 官方周边资料 |

组合与艺人筛选影响来源选项；更换组合、艺人或来源时清除不适用的实体／版本。选项支持搜索、加载提示、失败重试；旧请求的延迟返回不能覆盖新筛选。来源大类和具体资料仍可选填。

不知道来源时选「不确定」，填写获取渠道、时间或其他线索。知道来源但官方暂缺时选「其他」或「其他 / 官方暂未收录」，填写备注；这两种模式不会提交不适用的官方实体 ID。

已有专辑却缺少版本，可点击「没有所需版本？反馈缺失版本」。缺少整个专辑、活动或周边，则选择「反馈图鉴缺失内容」；图鉴搜索下方也增加了独立入口。提交需名称和说明，只进入运营审核，不自动创建／发布官方内容。来自扫描的反馈带上会话、检测对象与裁剪信息，提交后返回原表单，已有备注和选项保留。

## API 与数据

新增 `GET /api/v1/scan/feedback-options`，参数为 `source`、可选 `group_id`、`idol_id`，返回 `{source, source_mode, items}`。每项包含 `id`、`name`、`entity_type`、`subtitle` 和 `versions[{id,name}]`。

扫描反馈 metadata 增加 `source_mode`（KNOWN／UNCERTAIN／OTHER）、`source_entity_type`、`source_entity_id`、`source_version_id`。服务端验证公开状态、来源类型、组合／艺人及版本归属，并从官方数据解析可信名称。旧客户端不传新字段仍兼容。

这些字段存入已有 `ScanFeedback.payload`，无需新增数据库迁移。反馈历史返回并展示官方来源与版本名称。不修改扫描原图、候选真实性或收藏数据模型。旧专辑只有版本名称数组时，服务端生成稳定的只读引用并重新校验；GET 不写数据库。现有运营版本记录由公开父来源决定可见性，归档／下架版本不返回。

批量喜欢和拥有复用 `POST /scan/sessions/{id}/confirm` 的 `selected` 与 `add_to_wishlist`；图鉴缺失反馈复用 `POST /catalog/feedback`，进入已有后台审核队列。完整字段见更新后的 `contracts/openapi/fan-os-v1.yaml`。
