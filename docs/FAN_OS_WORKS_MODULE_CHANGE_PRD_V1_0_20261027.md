# Fan OS「卡册」升级「作品」变更 PRD V1.0

| 属性 | 内容 |
| --- | --- |
| 日期 | 2026-10-27 |
| 状态 | 需求评审稿；已确认规则与本稿建议分别标注，尚未实现 |
| 变更目标 | 将卡册模块升级为作品入口，预留砖卡、Live小卡，升级通用作品收藏 |
| 适用范围 | App、管理后台、服务端接口、存量兼容与验收 |
| 基线 | 《Fan OS 卡册 PRD V1.1》《Fan OS 小卡 Live PRD V1.0》 |

## 1. 背景与目标

原「卡册」入口扩展为「作品」，用于承载用户创作的卡册、砖卡和Live小卡。第一阶段保留卡册全部既有业务行为，新增两类仅保留入口与占位页；同时将卡册收藏升级为可按类型分类的通用作品收藏。

本次不是将现有卡片模式改成砖卡。现有 BOOK（相册模式）、CARDS（卡片模式）均继续归属卡册，保存、编辑、阅读、发布、审核与额度规则沿用原卡册规则。

## 2. 用户已确认规则

| 编号 | 规则 |
| --- | --- |
| R01 | 原「卡册」模块改名为「作品」 |
| R02 | 不设「全部」作品类型，固定展示「卡册(n)｜砖卡(n)｜Live小卡(n)」 |
| R03 | 砖卡、Live小卡本期先留位，不开放具体制作功能 |
| R04 | 每个类型统计自己的本人创作内容；收藏他人的作品不计入本人创作数量 |
| R05 | 本人主页与访客主页均展示三个类型 Tab |
| R06 | 现有卡册隐私设置仅作用于卡册；新增类型不得继承为默认公开 |
| R07 | 现有额度称「卡册数量」；砖卡、Live小卡有各自的额度 |
| R08 | 卡册收藏升级为通用作品收藏，支持分类 |

下文涉及默认选中、计数细节、收藏分组及异常展示等未逐项确认的交互，作为本稿推荐方案供评审；不将推荐视为已上线能力。

## 3. 本期范围与非目标

### 3.1 本期交付

- 作品入口更名及关联文案调整。
- 三类作品 Tab、独立数量与占位页。
- 本人及访客主页适配。
- 通用作品收藏的数据标识、类型筛选、自定义分组及原卡册收藏兼容。
- 卡册隐私、额度和后台分类口径澄清。
- 权限、分享跳转及旧客户端兼容。

### 3.2 本期不交付

- 砖卡效果编辑、渲染、素材配置、导出。
- Live小卡生成、视频任务、播放交付、Live Photo、生成计费。
- 将砖卡或视频嵌入卡册，以及不同类型之间转换、组合加工。
- 新类型额度数值、购买规则或权益售卖；本期不展示未生效权益。
- 新增作品广场、推荐、点赞评论体系或独立网页分享。

## 4. 分类与信息架构

### 4.1 分类层级

| 层级 | 分类 | 本期状态 |
| --- | --- | --- |
| 作品类型 | 卡册 | 可用，保留原功能 |
| 作品类型 | 砖卡 | 占位 |
| 作品类型 | Live小卡 | 占位 |
| 卡册内部模式 | BOOK／CARDS | 既有固定模式，不改归属 |

作品类型与卡册模式是不同维度；后台和接口不得将 BOOK、CARDS、砖卡、Live小卡作为同一级分类混用。

### 4.2 App 结构

```text
收藏（原一级导航保留）
├─ 已拥有
├─ 心愿单
└─ 作品（原卡册入口）
   ├─ 我的作品
   │  └─ 卡册(n)｜砖卡(0)｜Live小卡(0)
   └─ 作品收藏
      ├─ 卡册(n)｜砖卡(0)｜Live小卡(0)
      └─ 分组筛选

个人主页（本人／访客）
└─ 作品
   └─ 卡册(n)｜砖卡(0)｜Live小卡(0)
```

「我的作品／作品收藏」为内容范围切换，建议沿用现有本人内容与收藏内容的入口位置，避免再增加一级导航。具体排版由交互设计确定，但两者必须有清晰标题，不得将收藏内容混入本人创作列表。

没有「全部」作品类型。收藏中的「所有分组」只表示不限制分组，仍受当前作品类型限制，不构成「全部作品」Tab。

## 5. App 页面需求

### 5.1 作品入口与列表

1. 原入口「卡册」显示为「作品」，默认选中卡册。
2. 类型顺序固定为卡册、砖卡、Live小卡；使用实际数量，示例数字不作为数据。
3. 卡册列表保留原布局、排序、封面、创建、编辑、删除及阅读行为。
4. 卡册 Tab 显示「新建卡册」，继续使用现有 BOOK／CARDS 选择与创建流程。
5. 砖卡、Live小卡 Tab 可切换，显示类型名称及「敬请期待」，数量为 0；不展示创建、购买、生成、上传或收藏按钮。
6. 占位页不创建草稿、任务、素材记录或额度占用。
7. 切换类型建议保留卡册滚动位置；返回作品入口时默认卡册，现有带目标的跳转按目标进入。

### 5.2 本人与访客主页

- 原卡册展示入口更名为作品，均展示三个类型 Tab。
- 本人可管理自己的卡册，看到本人有权读取的草稿、私密和受限制内容；访客不得展示本人管理按钮。
- 访客只展示同时满足作品可访问条件和主页隐私条件的卡册；数字与实际可访问列表一致。
- 关闭「公开我的卡册」后，访客卡册数量显示 0，并显示「暂无可查看的卡册」；不暴露真实私密数量。
- 新类型占位不受卡册隐私开关控制，仍展示 Tab 与 0 数量；未来启用时另行定义独立隐私控制，默认不得公开。
- 公开收藏分组继续通过现有入口访问，不在作者创作列表中混排。

### 5.3 文案边界

| 场景 | 文案规则 |
| --- | --- |
| 聚合入口 | 作品、我的作品、作品收藏 |
| 卡册具体操作 | 新建卡册、编辑卡册、删除卡册 |
| 隐私 | 公开我的卡册 |
| 数量额度 | 卡册数量 |
| 未开放类型 | 砖卡／Live小卡；敬请期待 |

不进行全项目机械替换；图鉴中的实体专辑、卡册具体业务以及旧链接标识按实际语义保留。

## 6. 数量与额度

### 6.1 推荐计数规则

| 场景 | 数量定义 |
| --- | --- |
| 本人创作 Tab | 当前类型下本人创建、未删除且本人可读取的作品数；卡册包含草稿、私密及本人可见的受限作品 |
| 访客创作 Tab | 当前类型下符合访客访问及主页展示权限的作品数；不统计草稿和不可访问内容 |
| 本人作品收藏 Tab | 当前类型下有效收藏关系数；保留的失效引用也计入，以便与可管理条目一致 |
| 访客公开收藏分组 | 当前分组、当前类型下可访问作品数；不暴露失效或私密引用数量 |
| 未开放类型 | 固定为 0；加载失败不可伪装成 0 |

类型 Tab 数量代表当前内容范围下该类型的总数，不随分组筛选变化；分组筛选后的结果数单独展示。访客访问具体公开分组时，其内容范围即该分组。列表分页时数量使用服务端总量，不取当前页长度。

收藏同一作品在类型总数中只计一次；本人收藏引用失效时显示不可访问条目，不显示缓存封面、原名称等可能泄露的内容。移除后数量递减。访客不展示失效占位。

### 6.2 额度规则

- 原卡册作品数额度更名为「卡册数量」，BOOK／CARDS 继续共用原卡册数量额度。
- 页数、卡片容量、取色等既有子额度不变。
- 收藏他人作品不消耗本人卡册数量，也不消耗未来其他类型的创作额度。
- 砖卡、Live小卡未来各自配置额度，不从卡册额度中扣减，不因本期上线重新发放权益。
- Tab 内容数量与额度占用是两个字段，沿用既有额度校验，不由前端展示数量推导是否允许创建。

## 7. 通用作品收藏

### 7.1 类型分类与自定义分组

系统分类按卡册、砖卡、Live小卡划分；自定义分组用于用户整理，两者是独立筛选维度。

- 本期只有卡册可以实际收藏，另两类显示占位。
- 分组的数据结构支持未来容纳多种作品类型，本期不产生虚构的新类型内容。
- 沿用现有创建分组、改名、公开设置、移动收藏、取消收藏能力，不改变原分组归属规则。
- 类型与分组筛选可以组合；切换分组不改变作品类型。
- 推荐默认卡册＋所有分组，保留未分组视图；不新增跨类型全部列表。
- 不能收藏自己的作品；对同一目标重复点击、重试或并发请求只保留一条有效收藏关系。
- 本期不将此前未完成的完整分组删除入口视为已有能力，是否新增另行排期。

### 7.2 收藏访问规则

收藏保存对原作品的引用，不复制作品，不增加本人创作数量或实体小卡拥有数量。原作者重新发布后，收藏读取最新合法发布版本，不能读取未发布编辑内容。

原作品转私密、删除、受限或下架后：本人收藏保留可移除的失效引用；访客公开分组不展示该作品；历史链接、缓存、类型筛选和分组筛选均不能绕过权限。原作品恢复可访问后，按其当前合法版本展示。

分组公开只决定是否允许访问分组，不能代替作品自身公开授权。私密分组及其数量仅所有者可见。

### 7.3 存量兼容

所有现有卡册收藏归入卡册类型，保留收藏时间、目标 ID、分组关系、分组名称及公开设置，不要求重新收藏。不因升级重复计数、重新排序或产生额外卡册。

## 8. 后台需求

| 位置 | 本期要求 |
| --- | --- |
| 导航 | 原数字相册业务入口升级为「作品管理」；子页面仍明确卡册业务范围 |
| 卡册列表 | 保留查询和操作，将原 BOOK／CARDS「作品类型」字段明确为「卡册模式」 |
| 作品类型 | 当前可管理类型仅卡册；不新增无业务能力的砖卡／Live列表与操作入口 |
| 详情与预览 | 明确「作品类型：卡册」「卡册模式：相册／卡片」，沿用对应编辑、发布和复核快照预览 |
| 额度与会员 | 原作品总数配置显示为「卡册数量」，保留原数值、用户授权及降低额度保护 |
| 素材管理 | 书架主题、封面、内页、卡片背景继续归属卡册，不能自动获得新类型适用权限 |
| 审核与举报 | 原卡册权限与流程不变；现有记录归属卡册，不新增视频审核或砖卡效果审核 |
| 收藏数据 | 若现有报表或详情涉及收藏，统一类型标识与统计口径；本期不新增用户收藏管理控制台 |
| 权限 | 原卡册管理角色继续只拥有卡册管理能力，不隐式授予未来新类型权限 |

后台名称升级不代表已经具备三类业务管理能力。新类型素材、额度具体参数、生成任务和专用审核页面随其功能 PRD 另行交付。

## 9. 服务端与接口约束

以下为业务契约要求，不指定必须采用某个新路由，也不要求将原卡册整体迁移到通用大表。

1. 建立明确的作品类型标识，建议使用 ALBUM／BRICK／LIVE；BOOK／CARDS 保持为卡册内部模式，最终命名在技术设计中统一。
2. 通用收藏目标至少包含作品类型与作品 ID，联合标识唯一；不能仅以裸 ID 判断目标。
3. 收藏查询支持目标用户、作品类型、分组与分页；计数使用与列表一致的用户视角和权限条件。
4. 分组为用户级分组，关联目标可扩展到不同类型；保留原归属与移动语义，不额外引入多分组规则。
5. 未开放类型拒绝创建、收藏及修改请求，返回明确未开放信息；不能只隐藏 App 按钮。
6. 未知作品类型不得按卡册解析或静默丢弃；旧客户端应得到明确兼容提示，不混入其无法处理的新类型。
7. 保留原卡册接口及分享链接的兼容能力；适配层读写必须指向同一份有效数据，避免新旧接口各存一份。
8. 所有列表、详情、收藏、分享、计数统一执行服务端权限检查；不能依赖客户端传入“本人”标记。
9. 收藏公开计数、私有计数与分页缓存必须区分查看者权限；隐私变化后更新相关结果。

## 10. 数据兼容与发布

- 卡册 ID、作者、模式、内容、创建时间、发布版本、复核记录与原隐私配置全部保留。
- 不将现有 CARDS 作品迁移为砖卡，不拆分或合并原卡册。
- 原收藏补充类型映射时须可重复执行且不重复建关系；原 ID 冲突按类型联合标识处理。
- 原卡册分享链接继续进入对应模式阅读器，旧通知和收藏目标继续可用。
- 上线顺序建议先完成服务端兼容及数据校验，再更新 App 与后台文案和入口。
- 回退时保留新增类型标识与映射的可恢复信息；旧版本仍可读取原卡册与收藏。
- 本文不执行迁移、不修改代码，也不授权生产发布。

## 11. 异常与状态

| 场景 | 预期行为 |
| --- | --- |
| 卡册为 0 | 显示正常卡册空状态；本人可创建，访客无创建按钮 |
| 切换未开放类型 | 显示敬请期待、数量 0，不发起创作任务 |
| 数量或列表加载失败 | 展示失败及重试，不将异常解释为没有作品 |
| 原卡册被删除或转私密 | 创作与访客计数按权限更新；本人收藏显示失效引用，访客过滤 |
| 收藏请求重试 | 不重复收藏、不重复计数 |
| 分组中没有当前类型 | 显示该类型在本分组暂无收藏，不自动切换到其他类型 |
| 旧客户端请求新类型 | 明确未支持或升级提示，不能误开卡册阅读器 |
| 后台降低卡册额度 | 沿用历史内容保留和影响确认，不能删除超额卡册 |

## 13. 与既有需求的关系

- 卡册 PRD V1.1：本稿覆盖作品入口名称、分类、通用收藏及相关统计口径；未涉及的卡册内部行为继续按原文执行。
- Live PRD V1.0：原「收藏页新增独立动态卡 Tab」与独立动态作品入口的规划，调整为「作品 → Live小卡」。具体生成能力仍留待后续实现，本稿不提前启用原 Live 交付或权益。
- 后续砖卡、Live小卡功能 PRD 必须补充独立额度、隐私、收藏访问、预览、审核与类型启用方案，不得直接继承卡册的公开授权与管理权限。

## 14. 评审重点

已确认规则见第 2 节。本稿新增的推荐细节重点包括：本人收藏计数包含可移除失效引用、类型数量不随分组筛选变化、跨类型共用自定义分组、后台入口命名。评审可调整这些细节，不影响三类作品架构与两个新类型占位的已确认范围。
