# Fan OS 会员体系与云费用盈亏测算

版本：V0.1 · 讨论稿，未实施  
更新日期：2026-10-14  
成本口径：用户确认只计算云费用，暂定 ¥2,000/月，不计运营、人力和获客成本。  
金额：人民币；文内权益、价格、使用率均为建议或测算假设，不代表已生效规则。

## 1. 当前建议

首期推出“免费用户 + PRO 会员”，附加一个独立扫描次数包；暂不增加复杂的会员等级。

建议讨论价格：**月卡 ¥15，年卡 ¥128**。核心权益为扫描额度、更多卡册和内页、会员装饰素材；普通取色和已有基础收藏能力保持免费。

在每月 ¥2,000 云费用已覆盖全部日常扫描、存储和流量的前提下，按月卡用户占 40%、年卡用户占 60%、渠道扣费 15%、退款准备 2%测算：

- 单个有效付费会员月均净收入约 ¥10.33。
- 约 **194 个有效付费会员**覆盖云费用，200 人只是略微超过盈亏线。
- 建议把 **300 个有效付费会员**作为第一阶段持续覆盖云费用的目标：月均净收入约 ¥3,099，扣云费用后余量约 ¥1,099。
- 如果付费渗透率为 5%，300 名付费会员对应约 **6,000 MAU**；如果为 2%，对应约 **15,000 MAU**。

这里的“收益”是扣渠道、退款准备及云费用后的余额，不是包含人力、税费、运营和获客成本的企业净利润。¥2,000 也不是无限容量保证，云费用随规模上涨时必须重算。

### 3.2 扫描怎么扣次数

建议用用户能看懂的“张数”，而不是容易引起争议的“点击次数”。

1. 一张照片中勾选 5 张小卡，运行匹配消耗 5 张额度；取消勾选的不消耗。
2. 打开相机、选照片、编辑检测框不消耗扫描额度，但检测接口仍需频率限制，防止免费检测耗尽算力。
3. 额度在任务开始时预占，完成后按实际执行匹配的张数结算；并发请求不能绕过剩余额度。
4. 服务不可用、图片读取失败、索引不可用等系统失败退回额度。正确执行但没有匹配结果仍计入，并在提交前说明“有效分析包含未识别结果”。
5. 同一任务的网络重试不重复扣费；主动重新分析新图片才扣费。额度记录需关联任务、用户和张数。
6. 多卡任务部分失败，成功执行部分正常计量，系统失败部分退回；不得把任务重试当作全量新扣费。
7. 剩余额度不足时提示减少勾选、购买次数包或开通会员。每次耗费张数在确认按钮附近展示。
8. 免费额度按上海时区自然月重置；会员按订阅权益周期每月发放，年卡每月发放 300 张，不一次发 3,600 张。
9. 当月已有使用量在升级时沿用，额度上限从免费提升至 PRO，不能反复升级/降级刷新增赠送。完整跨周期结算口径在接口设计时锁定。
10. 未使用的会员月额度不结转。订单退款、补发和人工调整都通过额度账本留痕。

额外扫描包建议：**¥6 / 100 张**，有效期 180 天，免费用户也可购买。先用较早到期的免费/会员额度，再使用较早到期的付费额度；系统失败退回原额度来源。月卡/年卡与次数包均是提案，具体售价档位以发行渠道可配置 SKU 为准。

按 15%渠道扣费和 2%退款准备，次数包净收入约 ¥4.998，每张约 ¥0.05。若未来每张扫描新增成本达到 ¥0.03，100 张包剩余贡献约 ¥1.998，还未分摊固定云费用；若超过约 ¥0.05/张，该价格基本失去余量，应提价或减少张数。

### 3.3 取色器是否应该按次数收费

取色器需要拆成三个功能，不能把它们统称为 AI：

| 类型 | 处理方式 | 建议收费方式 |
| --- | --- | --- |
| 普通颜色选择 | 选预设颜色、输入 HEX、调渐变 | 免费 |
| 图片取色 | 从已加载的图片提取主色或点选像素，优先端侧实现 | 免费，或少量体验后 PRO 解锁；不按云扫描价格计成本 |
| AI 配色 / 风格生成 | 识别风格、推荐多套配色、生成背景等 | 后续作为独立权益计次，按真实调用成本测算 |

如果图片取色需要下载一张新图片，可能产生图片流量；但取色算法本身不必产生外部 AI API 费用。取色器作为小增值可用，首期不应成为频繁弹窗收费的主要入口。

### 3.4 “官方贴图的使用范围”怎么定义

这里需区分两种素材：

- **官方图鉴小卡图片**：是卡册的核心内容引用，建议维持现有可见性及图片可用性规则，不按会员挡住全部小卡。
- **平台提供的装饰贴图/贴纸/背景**：可以划分 FREE、PRO、独立素材包，会员解锁装饰范围。

素材配置包含 `resource_id`、类型、所属素材包、所需权益、允许使用位置（封面/内页/书架）、发布状态与使用限制。现有系统符号贴纸不等于所有位置均已支持自由贴图，内页自由贴图需另评估编辑器和保存校验。

首期范围：在已支持的位置使用会员素材；新增内页贴图或新增图片素材能力必须单列开发项。发布时服务端检查权限，不能只在 App 把素材置灰。

会员到期后，原作品已使用的素材继续展示；允许移动、缩放、删除等维护操作，不允许新增或复制会员素材实例。再次开通恢复新增使用。付费素材包按购买时约定保留权益。素材因平台下架不可用时按现有内容可用性规则处理，不承诺会员永久访问下架素材。

## 4. 还能考虑哪些场景

优先选择用户能感知的“收藏管理效率”和“作品表达”，不把收费建立在大量未开发功能上。

| 场景 | 产品价值 | 当前基础 | 收费建议 | 优先级 |
| --- | --- | --- | --- | --- |
| 专题装饰素材包 | 回归季、收藏风格、节日卡册装饰 | 已有系统素材管理 | PRO 包含部分；独立包 ¥6–18 作为测试价格 | 高 |
| 更多卡册容量 | 重度收藏者按组合、艺人、活动分类 | 已有额度能力 | PRO 先沿用 30 本 × 20 页 | 高 |
| 扫描次数包 | 偶尔集中整理小卡，不愿持续订阅 | 有扫描，没有支付额度账本 | ¥6 / 100 张，和会员分开 | 高 |
| 收藏统计 | 按组合/艺人/专辑统计数量、重复卡与缺卡 | 已有图鉴、拥有和心愿单数据 | 基础统计免费，深度筛选/汇总 PRO；新增统计能力 | 中 |
| 一键生成收藏册 | 按已拥有、组合、艺人等自动排版 | 已有选卡、布局和卡册数据；不是完整自动排版 | PRO 增值，需新增规则及预览确认 | 中 |
| 高清作品导出 | 输出卡册封面/内页展示图 | 分享阅读已存在，高清渲染导出未确认 | 基础分享免费，高清导出 PRO，设月额度 | 中 |
| 收藏数据备份 / 导出 | 重度收藏者的长期数据管理 | 有账号数据，不等于已有导出功能 | 原始个人数据基础导出保持可用，排版报表等增值 PRO | 中 |
| 主页个性化 | 主题、展示背景、会员徽章 | 有个人主页；高级装饰需新增或扩展 | PRO 附加权益，不作为主卖点 | 中 |
| 特定条件的新卡提醒 | 关注组合/艺人的新收录卡、缺卡补全提醒 | 关注、图鉴和消息有数据基础，规则需新增 | 基础提醒免费，精细条件 PRO | 后续 |
| AI 智能背景、自动设计 | 新配色、生成素材、风格匹配 | 未确认已接入生成服务 | 单独计次 / 单独包，实测成本后定价 | 后续 |

不建议首期收费的内容：图鉴查看、反馈提交、反馈处理资格、已收录贡献署名、个人基础收藏与基础分享。贡献可获得奖励，但付费不改变审核采纳标准。

贡献奖励可试行：每张真实新收录的小卡奖励 10 张扫描额度，单用户每月最多 50 张，30 天有效。先按贡献判重后发放，防止多条重复反馈刷额度；奖励产生的云负载必须计入整体扫描量。该方案待讨论，不写进首期默认承诺。

## 6. 成本模型与计算口径

### 6.1 主模型参数

| 参数 | 当前值 | 性质 |
| --- | ---: | --- |
| 固定云费用 F | ¥2,000/月 | 用户给定预算；主模型视为扫描算力、数据库、存储、流量等总云预算 |
| 月卡价格 | ¥15 | 建议 |
| 年卡价格 | ¥128 | 建议 |
| 月卡用户占比 | 40% | 测算假设 |
| 年卡用户占比 | 60% | 测算假设 |
| 支付渠道扣费 f | 15% | 测算假设；渠道、地区、商品和资格不同会变化 |
| 退款准备 r | 2% | 风险余量假设，不是已知退款率 |
| 运营 / 人力 / 获客 | 不计 | 用户指定范围 |
| 税费及独立版权采购费 | 暂未计 | 没有实际金额，不能将本稿余额称为企业净利润 |

渠道扣费不是运营费用，但会减少收入，所以单列。苹果 Small Business Program 对符合条件并获批准的开发者提供 15%佣金；不能默认所有账户都已获批准。[Apple 官方说明](https://developer.apple.com/app-store/small-business-program/)

Google Play 当前费用按地区和商品类型区分，自动续订订阅在所列口径中通常合计为 15%；实际发行市场和账单仍需核对。本稿统一按 15%做情景计算，不当作全球渠道通用事实。[Google Play 官方说明](https://support.google.com/googleplay/android-developer/answer/112622?hl=en)

对象存储的账单包括存储、出网流量、读写请求等，不能只乘图片容量。本稿没有虚构具体云厂商报价，先沿用 ¥2,000 的总预算，实际账单按地区及资源配置替换。[阿里云 OSS 计费说明](https://help.aliyun.com/zh/oss/billing/)

### 6.2 公式

```text
P = 当月有效付费会员数（包括权益仍有效的年卡用户）
MAU = 当月活跃用户数
p = P / MAU（本稿假定有效付费会员当月均活跃，用于换算量级）

混合月均售价 A = 15 × 40% + (128 / 12) × 60% = 12.40
单会员月均净收入 R = A × (1 - 15%) × (1 - 2%) = 10.3292
月净收入 = P × R
云费用后余额 = P × R - 2,000
盈亏会员数 = ceil(2,000 / R) = 194
对应 MAU = ceil(P / p)
```

年卡按有效期分摊作管理测算；不是完整会计收入确认规则。若部分年卡用户当月不活跃，P / MAU 的值会变化，不能拿“当月新付费人数 / MAU”替代本模型的存量有效会员比例。

| 有效付费会员数 | 月均净收入 | 云费用 | 云费用后余额 |
| ---: | ---: | ---: | ---: |
| 100 | ¥1,033 | ¥2,000 | -¥967 |
| 194 | ¥2,004 | ¥2,000 | +¥4 |
| 200 | ¥2,066 | ¥2,000 | +¥66 |
| 300 | ¥3,099 | ¥2,000 | +¥1,099 |

### 6.4 不同付费渗透率对应 MAU

## 7. 扫描增加成本时，体量是否仍能覆盖

### 7.1 先避免重复算成本

当前扫描是本地云服务器处理，CPU 支出若已含在 ¥2,000/月内，主模型不能再把同一笔 CPU 费用按张重复计入。

以下只计算 **¥2,000 云预算之外的增量成本**：例如加机器、实际超出的图片流量，或未来增加的外部识别 API。每张 ¥0.002 / ¥0.01 / ¥0.03 是人为压力测试，不是现有扫描供应商报价。

测算使用：免费用户平均 8 张/月，付费用户平均 80 张/月。平均用量与权益上限不同，不能假定人人用满，也不能只按低平均用量承诺高额度。

```text
c = 每张增量成本（不含已计入固定预算的部分）
s_paid = 80；s_free = 8

单会员可用于覆盖固定云费的贡献 M
  = R - c × s_paid - c × s_free × (1 - p) / p
盈亏会员数 = ceil(2,000 / M)，仅当 M > 0 有意义
```

| 每张预算外增量成本 | p=2% 所需会员 | p=5% 所需会员 | p=10% 所需会员 |
| ---: | ---: | ---: | ---: |
| ¥0（已含在云预算） | 194 | 194 | 194 |
| ¥0.002 | 214 | 203 | 200 |
| ¥0.01 | 357 | 250 | 228 |
| ¥0.03 | 单会员贡献为负，扩大规模无法覆盖 | 594 | 347 |

在 ¥0.03/张、2%付费渗透率下，每增加一个会员，同时对应大量免费用户扫描，收入不足以覆盖这组增量成本；不是多拉用户就能解决。需要提升付费渗透、控制免费月额度、降低单次处理成本或调整价格。

### 7.2 免费和会员用满的压力测试

以 6,000 MAU、300 个有效会员（5%）为例：

| 使用情景 | 免费用户扫描量 | 会员扫描量 | 合计 |
| --- | ---: | ---: | ---: |
| 平均用量：8 / 80 张 | 5,700 × 8 = 45,600 | 300 × 80 = 24,000 | 69,600 张/月 |
| 用满提案额度：30 / 300 张 | 5,700 × 30 = 171,000 | 300 × 300 = 90,000 | 261,000 张/月 |

月均 69,600 张不代表瞬时压力低。需要测试单卡/多卡、图鉴索引大小、并发峰值、检测与匹配各阶段时延，再确认 ¥2,000 的机器预算能否承载。

若按新增 ¥0.01/张计成本，平均场景增加 ¥696，300 名会员云费用后余额降至约 ¥403；用满场景增加 ¥2,610，余额为约 -¥1,511。这个结果说明：300 人目标成立依赖现有云预算容量及真实使用分布，不应承诺无限扫描。

## 8. 云费用里最值得盯的部分

1. **扫描算力**：分别记录检测和单卡匹配 CPU 时间、任务耗时、队列等待。图鉴图片越来越多时，本地匹配成本也可能上涨。
2. **图片流量**：列表用缩略图，详情按需加载，正反面避免重复下载；共享图鉴图、缓存和 CDN 能减少重复访问成本。
3. **扫描图片存储**：普通历史原图建议设可配置留存期，例如 30 天；已进入反馈审核的图片单独管理，不能自动清理仍待审证据或已收录来源记录。保留成本计入预算。
4. **卡册结构存储**：卡册引用已有图鉴，内页数量主要增加 JSON、引用和请求量，不等于每个卡位再复制一份原始图片。
5. **个人照片与未来自传贴图**：这是独立上传容量，不能混同数字卡册本数。若未来推出私人图片云空间，需要以 MB/GB 定义权益，再计存储、流量及处理费用。
6. **流量、数据库和请求增长**：每周看真实账单；云费接近预算的 80%时检查预测与容量，不凭会员人数推断云费不变。

建议的台账：按月记录云账单分项、MAU、有效会员、扫描总张数、免费/会员平均和 P95 使用量、出网 GB、扫描图存储 GB、新增付费与退款。每月把真实值替换到本稿。

## 9. “稳定收益”的可验收定义

按本次范围，建议称为“稳定覆盖云费用”，满足以下条件再判断达标：

- 连续 3 个月，扣渠道与退款准备后的月均收入覆盖实际云账单，且保留至少 30%收入余量。
- 会员规模至少 300 人；若实际云账单高于 ¥2,000 或增量成本上升，按实际公式提高人数目标。
- 不依赖当月集中售出的年卡现金证明持续收入；年卡按有效月份分摊，同时跟踪剩余服务义务。
- 月卡取消、年卡到期、退款后仍能维持会员数，新增会员能抵消流失。
- 以 300 人作示例，若当月实际流失 5%，至少需补充 15 名付费会员维持人数。5%是示例，不是现有流失率；年卡需按到期批次跟踪续费。
- 有云费用和使用量监控，额度用满及高峰并发时不会形成无法承受的超支。

该定义是产品管理目标，不是对未来收益的保证。暂不计入次数包、素材包收入作为盈亏线，实际卖出后可作为额外收入单列。

## 10. 需要补哪些 App 与平台功能

### 10.1 App

- 会员页：价格、周期、扫描月额度、卡册额度、素材范围、到期规则及支付条款信息。
- 扫描页：本周期剩余额度、预计消耗张数、次数包入口、任务失败退额提示；AI 扫描 → 我的反馈统一承接两类反馈进度。
- 卡册书架 / 新增内页：显示已用/可用额度，在真实超额操作时提示升级，基础查看不强制弹购买框。
- 素材选择器：免费、PRO、已购包标识，可预览，应用时校验权限。
- 会员到期：作品保留，新权益使用受限；到期后的编辑、复制和素材新增边界一致。
- 支付完成恢复权益、恢复购买、多设备同步、取消续订后到期日展示。
- 我的贡献只展示已收录小卡，不放查看进度；贡献署名和查看不要求会员。

### 10.2 平台

- 会员套餐及 SKU：价目、周期、渠道、上下架、权益配置版本。
- 用户权益：来源为订阅/人工赠送/活动，开始与到期时间、撤销与操作记录。
- 扫描额度账本：发放、预占、消耗、退回、过期、补发、订单关联、防重复。
- 素材管理：FREE / PRO / 已购包，允许使用位置及素材状态。
- 支付订单与事件：支付、续期、退款、取消、账单重试、恢复购买；由服务端校验凭证并幂等处理。
- 收益及用量看板：净收入、云费用、有效会员、实际额度使用、各渠道退款与使用成本。

现有相册 PRO 可作为权益入口，但要增加全局权益定义；不能让后台手工 PRO、商店订阅和次数包各自成为相互覆盖的状态。后台赠送会员单独保留来源和到期时间，不伪造付费订单。
