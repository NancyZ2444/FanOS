## 1. 产品目标与范围

用户选择喜欢的图鉴小卡，使用少量预设效果，生成保留原卡人物、构图和收藏感的短动态作品。核心价值是让用户愿意反复欣赏自己的小卡，并可保存到手机。

一期包含：单卡选取、模板选择、生成确认、异步任务与恢复、个人动态库、全屏连续播放、视频保存、目标 iOS 设备 Live Photo 保存。公开审核、主页展示和平台链接作为一期第二批能力，在审核与访问控制就绪后开放。

本期不包含：任意相册照片上传、自由提示词、大幅动作或剧情视频、语音及声音模仿、批量生成、动态合集、BOOK / CARDS 嵌入视频、推荐广场、点赞评论、收藏他人动态。描述找卡独立建设，只通过原卡详情衔接本功能。

## 2. 现有应用与改造边界

以下为本地代码核对结果，不代表生产已部署。

| 现有位置 / 能力 | 已有基础 | 本次新增 |
| --- | --- | --- |
| Flutter 主导航 | 首页、图鉴、扫描、收藏、我的 | 保留五项，在现有页面增加入口 |
| 收藏页 | 已拥有、心愿单、卡册 | 第四个 Tab「动态卡」 |
| 个人主页 | 已拥有、心愿单、卡册、贡献及部分隐私控制 | 独立动态作品 Tab 与访客权限 |
| 小卡详情 | 图鉴卡展示与用户关系 | 「让小卡动起来」「我的动态作品 N」 |
| API 模块 | catalog、collections、albums、scan、notifications 等 | 新增 card_live 业务模块及 AI 能力适配层 |
| 模型接入 | card_matcher 扫描适配实现 | 新增图生视频适配，不把扫描服务当视频模型使用 |

| 文件存储 | LocalStorage / S3Storage；save_bytes 返回文件 URL | 私有作品对象、受控读取、临时授权、媒体处理 |

## 3. 主要用户场景

| 场景 | 用户行为 | 产品响应 |
| --- | --- | --- |
| 看到喜欢的小卡 | 详情点击「让小卡动起来」 | 带入当前卡，进入效果页 |
| 想让收藏里的卡动起来 | 从已拥有单卡菜单或动态库选卡 | 优先展示已拥有，也可切换全部可生成图鉴卡 |
| 等待期间继续使用 App | 离开页面或关闭 App | 后台继续执行，下次恢复原任务 |
| 欣赏不同成品 | 网格选作品，上下滑切换 | 只播放当前项，按当前筛选集合浏览 |
| 保存喜欢的效果 | 保存视频或 Live Photo | 按承诺档位交付；重复保存不扣次数 |
| 展示给同好 | 主动申请公开或导出分享 | 审核通过后公开；导出文件不自动公开作品库 |

生成不要求先标记已拥有。能否生成取决于源图片可用性、允许处理范围、效果支持和用户额度。自报拥有不是图像处理授权依据。

## 4. 信息架构与页面要求

### 4.1 入口

- 小卡详情：主入口「让小卡动起来」，下方「我的动态作品 N」。
- 收藏 → 已拥有：单卡操作增加「生成动态」。
- 收藏 → 动态卡：生成动态、作品网格、生成记录。
- 个人主页 → 动态卡：本人管理，访客查看公开作品。
- 描述找卡：先进入原卡详情，用户明确发起生成，不在搜索结果中自动生成。

首次上线仍保留收藏原默认 Tab。未登录时按现有登录流程承接并恢复选卡，不创建匿名付费任务。

### 4.2 选卡器

默认「我的已拥有」，可切换「全部可生成小卡」，支持搜索、组合 / 艺人筛选。无已拥有记录时提供全图鉴入口。不可生成卡显示原因，如图片质量不足、暂未开放、当前效果不支持。首期仅使用图鉴正面主图，不自动拼接背面或多卡。

### 4.3 效果与确认页

展示完整原卡、效果示例、预计等待说明、输出规格、消耗次数及默认私有提示。示例注明「效果示例」，不承诺本卡完全复现。

建议首期从微风、背景轻动、轻微表情等候选模板中，选出经测试稳定的少量效果。默认无声、单镜头、约 3 秒，保留原构图；供应商原始输出时长与最终交付时长可不同，后台按固定策略处理。分辨率、时长和文件规格须在模型验证后配置，提交前展示实际档位，不预先承诺未验证参数。

确认区示例：

> 生成 1 件动态作品 · 轻动态效果  
> 本次交付：App 播放 + 视频保存 + 1 张 Live Photo  
> 消耗：1 次动态生成 · 默认仅自己可见  
> [生成动态]

只有已适配设备才展示上述 Live Photo 档位。客户端声明设备信息，服务端根据适配规则确定可用档位，并在创建任务时固定规格与配置版本。

### 4.4 任务页与记录

用户可见状态：排队中 → 生成中 → 处理中 → 已完成；异常显示失败、取消处理中、已取消或状态待确认。处理中包括转存、质量检查、转码与格式封装。供应商返回成功不等于作品已完成。

允许离开页面；动态库提示正在生成的数量。回到 App 拉取未完成任务；前台按服务端建议间隔查询，后台停止高频轮询。完成通知优先复用现有通知业务，系统推送是否复用需核对通道，未启用推送也必须能通过记录找回结果。不显示未经测算的精确百分比或完成时间。

### 4.5 成品与动态库

动态库为双列静态封面网格，显示艺人、原卡、动态时长、公开状态。默认最近生成在前，支持艺人、来源卡、仅已拥有、公开状态筛选。显示「12 件作品 · 来自 8 张小卡」。未完成任务放生成记录，不混入成品。

点击作品进入全屏播放，按当前筛选队列上下滑；只播放当前项，离屏或进入后台暂停。保留完整卡面，不为铺满屏幕裁掉卡面；按网络策略预加载相邻少量作品。队列结束不插入推荐，返回保留网格位置和筛选。

成品操作：查看原卡、保存视频、保存 Live Photo、分享 / 申请公开、再生成、删除、效果反馈。再生成创建新任务并重新确认扣次，旧作品保留。

## 5. 数据关系与内容权限

- 已拥有、心愿单、卡册保持原有独立关系；生成不自动修改这些数据。
- 同一 Card ID 可关联多个作品；系统重试同一任务最多交付一个作品。
- 删除作品不减少实体拥有数量；取消拥有或会员到期不自动删除作品。
- 默认私有，作品归属用户；原图贡献者与动态作者分别记录。
- 生成检查、技术交付和公开审核分开记录，不用一个状态表示全部结果。
- 本人可查看允许保留的私有成品；访客仅能查看已公开、审核通过、技术可用且未受限制的作品。

公开流程：私有 → 用户申请 → 待审核 → 通过后公开 / 拒绝后保持私有。审核针对确定的作品版本；撤回、删除或转私有使申请失效，迟到审核结果不能重新公开。私有文件可由本人主动导出；平台链接必须校验公开状态。访客首期不开放下载作者原文件，可查看原卡后自行生成。

转私有或删除后停止签发媒体访问授权，并使平台缓存失效；已签发链接有剩余有效窗口，若要求即时撤回需使用受鉴权媒体网关。用户已导出的文件无法由平台撤回，分享页应清楚说明。

## 6. AI 模型接入设计

### 6.1 接入架构

App → Fan OS card_live API → 权限 / 输入 / 额度检查 → 持久任务 → 视频 worker → 图生视频适配器 → 后处理 worker → 私有媒体存储 → 作品交付。

与描述找卡共用 AI 配置、凭证管理、预算、审计与调用记录思路；查询短请求与视频长任务分别限流、并发和计费。现有扫描适配器继续独立工作，不要求扫描、文字理解、向量编码与视频生成使用同一模型。

建议新增统一能力标识 `image_to_video`；质量检查如使用视觉模型，则采用独立 `video_quality_check` 配置。Live Photo 封装是确定性媒体处理能力，不属于视频生成模型能力。首期不要求再调用大语言模型来改写每张卡的提示词。

### 6.2 供应商适配协议

适配层应提供：能力查询、提交生成、查询任务、取消任务（可选）、验证回调、解析结果与统一错误。各供应商参数和异步协议由适配器转换；不假设所有图生视频 API 兼容同一接口。

| 能力字段 | 用途 |
| --- | --- |
| 输入约束 | 图片格式、大小、尺寸、比例、真人图支持条件 |
| 输出能力 | 支持时长、分辨率、比例、文件格式及是否可静音处理 |
| 任务能力 | 异步提交、查询、回调、取消、供应商幂等支持 |
| 运行条件 | 并发、频率、超时、地域、数据处理约定与预算 |
| 版本 | 供应商、模型版本、适配器版本与效果模板兼容关系 |

App 只选择产品效果，不传供应商名称、密钥或任意模型参数。服务端将效果映射到已验证的模型与模板，固定输入版本、提示模板、生成参数、交付规格和价格 / 权益规则版本。后台修改只影响新任务。

真人艺人图片是否允许输入及输出是否可用，需要针对候选供应商逐项确认和真实样本验证；本文不指定未验证的模型、不承诺人物一致性。供应商选择不阻塞业务协议设计。

### 6.3 效果模板

每个模板配置名称、示例、适用图片范围、输入条件、动作描述、约束、模型路由、输出档位和版本。默认约束包含轻动作、保持人物与构图、避免新增人物或物件、避免口型表演、保护卡面文字。

模板约束不能代替成品验收。文字变形、脸部变化、手部异常等仍需在输出阶段检查。单人、多人、侧脸、遮挡、文字较多、低清等图像分别评测；未通过的类型限制生成，不默默更换成不符合用户预期的效果。

### 6.4 路由与故障切换

先以一个已验证主模型上线，备用路由需对同效果与交付档位独立验收。供应商明确未受理时可按策略切换；提交超时或状态未知时先查询原任务，禁止盲目向另一供应商再付费提交。无法确认时进入待核对，不向用户显示成功或立即重复扣次。

## 7. 异步任务、恢复与结算

1. 检查当前源卡、图片版本、处理许可、模板、设备档位、用户资格和额度。
2. 使用客户端幂等键与请求参数指纹，在事务中创建任务并预占额度；同键不同参数拒绝。
3. 通过持久任务表与可靠投递机制派发 worker；Redis 可用于队列或锁，但不能作为唯一任务与账本来源。
4. worker 保存每次供应商尝试及上游任务 ID；采用租约、超时接管和有限重试，避免进程崩溃重复提交。
5. 通过验证后的回调或主动查询更新状态；重复、乱序和迟到事件不能覆盖最终状态。
6. 成品转存平台私有存储，检查可解码性、规格、黑屏等技术问题，并对人物失真等做规则检查与抽检；可选模型质检单独计费，不能仅用模型自评当真值。
7. 生成封面、静音 / 转码及承诺格式；全部必需资源有效后，事务性创建唯一作品、结算预占并写通知事件。
8. 定期补偿未投递任务、过期租约、漏回调、未结算交付与孤立文件。

建议默认：每用户同时 1 个未完成生成任务；队列等待上限 30 分钟、生成核对时限 30 分钟、后处理最多 2 次重试，均可配置并须随模型实测调整。到达时限后原子结束用户交付并释放预占；上游继续核对成本，迟到成品不再发放或扣次。状态未知在该时限内保留预占，并明确展示，不能无限等待。

排队取消须与 worker 领取互斥，成功后释放预占。运行中取消只有供应商确认或平台确认可终止交付后才结束；取消处理中不提前退款。无法取消时提示仍将继续执行。最终取消与完成竞态由服务端一次性决定，最多结算一次。

## 8. Live Photo 与文件交付

| 档位 | 完成条件 |
| --- | --- |
| 视频档 | App 可播放视频、有效封面、可保存的视频文件均就绪 |
| 已适配 iOS Live 档 | 视频档资源 + 有效配对的图片与视频资源，封装校验通过 |

Live Photo 由配对图片、视频及所需元数据组成，服务端后处理与 iOS 原生保存桥接需联合设计，不能仅修改文件后缀。是否采用服务端封装或端侧辅助封装，在技术验证中确定，任务必须留存可恢复的交付资源。

Live 档封装失败优先只重试后处理，不重新调用视频模型；最终无法交付则失败退次，不以普通视频替代成功。视频档未来新增可选导出不追溯改变原承诺。系统相册权限拒绝或用户取消保存不属于生成失败，作品保留、允许重试保存，不重复收费。Android 首期仅承诺验证通过的视频能力，系统动态照片另行适配。

## 9. 权益与成本

### 9.1 免费、会员与购买权益

采用「免费体验次数 + 会员月度次数 + 动态生成次数包」，三类额度分别记录。首期面向用户使用“次数”，不引入通用 AI 点数换算；后台账本保留后续扩展能力，本权益不与描述找卡额度混用。

| 权益来源 | 发放与有效期 | 使用规则 |
| --- | --- | --- |
| 免费体验 | 每账号终身一次性 5 次，长期有效 | 不按月恢复；开通会员不清空剩余次数 |
| 会员月度 | 每个会员月 15 次，当期有效，不累计 | 按会员生效日计算周期；年费会员也按月发放 |
| 额外购买 | 会员和非会员均可购买次数包，首期长期有效 | 不强制开会员；与会员额度分别记录 |
| 失败补用 | 原会员额度退回时已过期，补发对应次数 | 自补发起 7 天有效，作为首期建议默认值 |

首次满足账号使用条件时仅发放一次免费额度；重复登录、重装、会员到期或重新开通不重新赠送。以服务端唯一发放记录防重，不能只依赖客户端状态。

会员月以开通锚点计算。例如 10 月 27 日开通，当期为 10 月 27 日生效时刻至 11 月 27 日同一时刻之前。服务端保存确定的周期起止时间，用户侧以北京时间展示；遇目标月份无对应日期，取该月最后一天，后续周期仍按原始锚点计算。年费会员每到周期发放 15 次，不一次性发放 180 次。

开通会员保留免费余额，另发当前首个周期 15 次。有效期内续费延长会员期限，不立即重复发当期次数；中断后重新开通按新的生效时间建立周期。发放按账号与会员周期唯一处理，支付重试、重复回调和任务补偿不能多发。

会员到期后，未预占的当期会员额度失效；免费剩余与购买次数保留，已生成作品仍可查看、播放与保存。到期前已成功预占的任务可继续交付并按原预占结算，不因跨周期额外扣次。每期发放以会员当时有效为前提，取消后续续费不影响已经支付的当前有效期。

### 9.2 消耗与退回

首期固定 **1 次 = 1 件标准动态作品**，包含 App 播放、视频保存及已适配设备承诺的 Live Photo，不按保存格式重复收费。后续高清、长时或高级效果如需不同点数定价，应另行评审并在提交前明确展示，不能追溯修改已创建任务。

消耗顺序：优先即将到期的会员次数及失败补用次数（两者按到期时间升序），再用免费次数，最后用购买次数。同到期时间使用固定顺序，账本记录实际来源，用户提交前可看到本次使用哪类额度。

提交预占，完整交付后结算；技术失败或最终取消释放到原额度。原会员或补用额度已过期时，补发对应数量的 7 天失败补用次数，关联原任务且仅补偿一次，不恢复整个已结束周期。免费与购买额度直接恢复原来源。主动再生成另扣一次；系统恢复、重试、重复播放、下载和保存不扣次。

单纯不喜欢有效成品不自动免费重做；明显失真等质量反馈进入人工复核，按公布规则退次或补偿。不得同时对同一失败重复释放、退次和补发。

免费与会员首期均同时最多 1 个未完成生成任务。额度代表可生成数量，不代表无限并发；暂不承诺会员专属生成速度。

### 9.3 权益展示与购买

动态库与确认页显示“还可生成 N 次”，N 为当前可用、未过期且未预占的额度合计。展开显示会员剩余及到期时间、免费剩余、购买剩余、失败补用及有效期；预占单列“生成中占用”，避免余额误解。

不足时保留选卡与效果，展示「开通会员：每个会员月 15 次」和「购买次数包」；会员用户以购买入口为主。支付完成返回原确认页并刷新余额，由用户确认后再生成，不自动付费调用模型。会员和非会员使用相同标准生成交付规格，差异首先体现在次数。

次数包规格与售价待真实成本测算后确定，不默认绑定自动续购。订单由服务端验证支付结果，按唯一订单发放，重复通知不重复入账。购买记录与额度账本可追溯；支付退款需关联原发放批次、处理已用和预占额度，具体退款与支付渠道规则为上线前待定项。

### 9.4 成本控制

真实成本统计包含全部供应商尝试、质检、后处理、存储、播放与导出流量；以每件有效作品成本评估，不只看单次模型标价。视频生成单独设日 / 月预算、并发和用户频率；预算不足停止接新任务并不扣次，保留已有作品访问和已接受任务必要的后处理预算。已有基础云预算不能直接视为覆盖视频调用。

## 10. 数据与 API 建议

以下为拟新增契约，最终路径按仓库规范调整。

| 对象 | 核心字段 |
| --- | --- |
| LiveEffect | 模板、版本、示例、输入约束、路由、规格、开关 |
| LiveTask | 用户、源卡 / 图片版本、模板与配置快照、交付档位、幂等键、状态、截止时间、额度关联 |
| LiveAttempt | 任务、尝试序号、供应商任务 ID、提交状态、模型版本、错误、成本 |
| LiveWork | 独立 ID、作者、源卡、输入快照、封面 / 视频 / Live 资源键、版本、技术与内容状态 |
| LivePublication | 作品版本、申请、审核、撤回、发布时间 |
| QuotaGrant | 用户、来源（免费 / 会员 / 购买 / 补用）、发放批次、会员周期或订单、总量、有效期、规则版本及唯一发放键 |
| QuotaLedger | 任务、额度批次、预占、结算、释放、过期、补偿及唯一业务键 |

建议接口：

- `GET /api/v1/card-live/entitlements`：可用总次数、来源明细、有效期、预占及当前会员周期。
- 次数包商品、订单与支付优先复用应用支付基础；不足部分新增，服务端验单后入账，不由客户端直接改余额。
- `GET /api/v1/card-live/effects`：当前可用效果与档位。
- `GET /api/v1/card-live/eligible-cards`：分页可选卡及不可用原因。
- `POST /api/v1/card-live/tasks`：源卡、效果、预选档位、幂等键；返回任务与最终确认快照。
- `GET /api/v1/card-live/tasks`、`GET /api/v1/card-live/tasks/{id}`：本人任务与恢复。
- `POST /api/v1/card-live/tasks/{id}/cancel`：申请取消。
- `GET /api/v1/card-live/works`、`GET /api/v1/card-live/works/{id}`：本人或授权公开列表 / 详情。
- `POST /api/v1/card-live/works/{id}/export`：校验归属、内容与档位后提供导出授权。
- `POST /api/v1/card-live/works/{id}/publication`：公开申请；撤回用明确操作接口。
- `DELETE /api/v1/card-live/works/{id}`：删除作品。
- `POST /api/v1/card-live/works/{id}/feedback`：质量反馈；公开内容举报单独分类。

所有接口校验用户身份和对象权限；列表分页、作品计数和播放队列使用同一可见性规则。生成前的确认信息过期或规格 / 额度发生变化时要求用户重新确认，不静默升级扣费档位。

## 11. 媒体安全与来源变化

私有原始输出、封面、视频和 Live 资源不放公开媒体路径。新增私有存储接口，服务端鉴权后提供短时媒体授权或受控流式访问；禁止仅靠前端隐藏 URL。供应商临时取图 URL 限时、限定源对象，不开放任意客户端 URL 下载，防止服务端任意地址请求。

密钥仅保存在服务端秘密配置中；后台只显示凭证引用及脱敏状态。回调验证签名、任务关联及防重放；下载供应商结果限制来源、大小和类型。日志不记录密钥、完整签名链接或不必要的用户材料。

原卡换图不重生成旧作品，保留输入版本与来源快照。普通下架停止新生成，旧作品按下架原因独立判断；涉及处理许可撤回或内容限制时可按源卡 / 图片版本追溯限制作品、公开与导出。删除作品立即逻辑隐藏，后台按批准的文件、供应商材料和审计留存周期清理；具体周期为上线前必须确定的配置，不无限保留原始材料。

## 13. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| LIVE-01 | 详情发起 | 原卡正确带入，规格与消耗清楚，默认私有 |
| LIVE-02 | 非已拥有卡 | 符合生成条件可使用，不自动声明实体拥有 |
| LIVE-03 | 不可用输入 | 明确原因，创建前拒绝，不预占或扣费 |
| LIVE-04 | 重复点击 / 网络重试 | 同参数同幂等键一个任务、一次预占 |
| LIVE-05 | 关闭 App / worker 重启 | 恢复原任务，不盲目重复提交供应商 |
| LIVE-06 | 重复 / 乱序回调 | 最多一件作品、一次结算，终态不倒退 |
| LIVE-07 | 上游未知 / 超时 | 先核对原任务，截止后退次，迟到结果不再发放 |
| LIVE-08 | Live 封装失败 | 单独重试处理；最终失败退次，不伪装成功 |
| LIVE-09 | 相册权限拒绝 | 保留成品，重试保存不扣次 |
| LIVE-10 | 同卡主动再生成 | 多个独立作品，原卡与实体拥有不变 |
| LIVE-11 | 网格与全屏 | 当前项播放，后台暂停，返回保留位置，无推荐插入 |
| LIVE-12 | 私有媒体越权 | 列表、封面、详情、视频与导出均拒绝非授权访问 |
| LIVE-13 | 公开撤回竞态 | 迟到审核不重新公开；平台入口与媒体授权按策略失效 |
| LIVE-14 | 取消与完成竞态 | 一次终态决策，无重复退次、扣次或成品 |
| LIVE-15 | 路由配置变更 | 在途任务保持配置快照，新任务使用新版本 |
| LIVE-16 | 来源换图 / 限制 | 旧输入可追溯，不自动重生成，限制按原因传播 |
| LIVE-17 | 预算耗尽 | 停止新生成且不扣次，已交付播放与任务后处理可继续 |
| LIVE-18 | 删除 / 会员到期 | 删除仅影响作品；到期不自动移除既有成品 |

| LIVE-19 | 免费发放 | 每账号终身仅 5 次，登录、重装和会员到期不重复赠送 |
| LIVE-20 | 月费 / 年费会员 | 每个有效会员月发 15 次，不累计；年费不提前发全年额度 |
| LIVE-21 | 升级 / 续费 / 到期 | 免费余额保留，续费当期不重复发，到期保留购买余额与作品 |
| LIVE-22 | 消耗顺序 | 即将过期会员 / 补用优先，再免费，最后购买；并发预占不超额 |
| LIVE-23 | 跨期任务失败 | 原预占来源可追溯，过期额度补发 7 天补用，重复回调不多退 |
| LIVE-24 | 次数包支付 | 非会员可买，服务端验单，重复回调只发一次，成功后不自动生成 |
| LIVE-25 | 余额展示 | 合计与来源、有效期、占用一致，过期额度不计可用次数 |

模型验收使用真实代表性卡面集，由人工对照原卡评价人物一致性、动作自然度、构图、文字与手部异常；同时验证实际等待时间、有效交付率和成本。具体上线阈值在试验前确定并签入验收记录，不以供应商演示或模型自评代替。Live Photo 必须覆盖目标 iOS 设备的系统相册保存与动态回放。

## 14. 实施顺序与待定事项

1. 技术验证：选择允许处理的真实卡面，验证候选模型、模板、输出质量与 iOS 封装保存，形成设备 / 图片 / 模板支持矩阵及成本记录。
2. 核心闭环：私有存储、额度账本、异步任务、适配器、后处理与恢复，接入移动端选卡、生成、网格、播放、保存。
3. 灰度验收：故障、重复提交、回调与取消竞态、预算、越权和真机格式验证；按质量数据限制支持范围。
4. 公开能力：审核、个人主页、平台链接、撤回与举报就绪后单独开放。

上线前待定：最终供应商 / 模型、开放卡范围与处理依据、效果名单、精确成品规格、设备矩阵、试验阈值、次数包规格与售价、支付渠道与退款规则、排队 / 执行时限、数据清理周期、通知通道。若宣传包含 Live Photo，则对应设备档位必须完成真机验收后开放。
