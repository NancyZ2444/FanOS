# 2026-10-28 全量发布

发布范围：当前本地图鉴与反馈流程、数字相册 V1.1、独立后台/App 认证、扫描和消息界面；Android 1.0.15（2026102807）。只提交源码、测试、文档及产品静态资源。数据库、用户素材、密钥、环境配置、安装包、运行日志及测试输出不进入 Git。

## 部署顺序

1. 确认线上工作区干净，在旧服务运行时执行 `backup.sh`，校验数据库归档、素材及索引备份，并保留旧镜像标签。
2. 服务器检出已推送的确定提交，构建 API、后台和两个图鉴 worker。保留现有 `.env.cloud` 和 Docker 卷，`AUTO_SEED=false`。
3. 将备份恢复到独立 PostgreSQL 数据库。在新镜像内先执行 `verify_migration.py snapshot`，再运行 Alembic 升级和 `compare`；核对受保护表、相册身份、卡片顺序和历史归档。
4. 停止公开后台及 worker 的写入入口，重新备份并记录快照；停止 API 后应用正式迁移，先比较数据，再初始化用户明确指定的管理员及 App 账号。
5. 初始化凭证仅通过私有部署输入处理，数据库仅存哈希；同手机号用户保留原 ID、资料及资产。不迁移通用测试验证码，不批量新增白名单。后台「App 用户管理 → 更多 → 重置密码」可由具备权限的管理员配置密码。
6. 启动服务并验证健康、管理员与 App 密码登录、原有图鉴/相册及素材读取；然后生成指向线上 API 的 Android APK。

## 迁移与回退

本次包含 `h620_album_operations`、`i622_album_work_types`、`j626_auth_boundaries`。V1.1 迁移将 CARDS 模式旧槽位转换为独立卡片实例，保存原草稿及已发布快照。不能只回退镜像或执行 Alembic downgrade。维护期间若校验失败，应使用同一份已验证数据库与素材备份恢复并启用对应旧镜像；开放写入后需要额外处理升级后的新增数据，不能直接覆盖恢复。

升级前旧登录令牌不满足新认证边界，用户需要重新登录。短信与第三方登录是否可用取决于现有服务配置，本发布不擅自开启提供商。Android 为现有签名的侧载测试包，不是应用商店发布。
